# 按需服务器资源监控

入口为“监控中心 → 服务器监控”，原 `/monitor` 检测页面保留。主机和宝塔面板列表的“监控”开关默认关闭；开启只保存偏好，打开监控页后才采集。离开、隐藏页面或暂停自动刷新后不继续发起自动采集，不提供后台历史曲线或新增报警策略。

默认 60 秒，可选 30／60／300 秒。客户端顺序请求，服务端使用共享快照、同目标互斥和两个全局租约槽；手动刷新不绕过 30 秒最短间隔。采集失败逐次退避至 300 秒，单台失败不会阻塞整页；较大分组需要分批加载，选择更短间隔不保证全部卡片能在该间隔完成。采样可能更新宝塔自身统计缓存和访问日志，不执行升级或网站变更。

宝塔使用已存 API 地址、密钥和 TLS 信任配置，不使用登录账号密码模拟登录。主机使用已存 SSH 凭据执行固定 Linux 只读脚本，不安装 agent。SSH 采集与宝塔 API 使用独立本机子进程限制墙钟、输出和回收；凭据只经 stdin 传递，不进入参数、文件或日志。实际占用随台数、网络和系统响应变化，不能据限流设置宣称没有额外负载。

一台主机可关联宝塔记录并合并卡片。仅当前账户可查看且已开启的来源参与展示和采集；API 优先，已开启 SSH 才能作为后备。相同 IP 仅提示候选，须用户确认关联，不将 NAT 或共享 IP 自动判为同机。原宝塔查看权限仍覆盖其整个列表，主机沿用分组权限；新增监控页面权限不会扩大来源访问权。

未知指标显示“—”；失败后保留的上次指标明确标记过期并保留原采样时间。字节与百分比经过归一化，磁盘多挂载点可以展开。资源指标只反映采样时刻，不证明网站业务健康。

## 构建与发布

前端在本机用 lockfile 构建；[package.py](package.py) 打包已提交的 API／部署源码和预构建静态文件，并输出源码版本与归档 SHA-256。服务器构建使用 [Dockerfile](Dockerfile)，从明确的现有镜像派生，仅复制 baota 模块和静态文件，不安装依赖或编译前端。

升级前确认无未完成任务和锁，在暂停写入后保存配套数据库、完整数据卷／加密密钥、Compose 和环境。三个新模型位于 baota app，启动时沿用 updatedb 生成增量迁移；不得覆盖已有迁移目录。先在禁止外联的克隆数据卷／数据库上验证新增表、默认关闭以及旧数据／密钥指纹，再正式切换。生产验收保持客户监控默认关闭，只有用户主动开启后才采集。

`preserve.py --require-idle` 用于停机前后私有指纹比较，包含原宝塔表、主机、模板、执行历史、设置和密钥，输出不含原始客户字段。结果与备份只放服务器权限 700 的目录，不提交仓库。

[release.sh](release.sh) 为本次发布的有前置断言的执行脚本，检查旧运行镜像与 Compose 版本后，完成备份、克隆演练、切换及验收。克隆使用临时卷、内网 Docker 网络及内存／CPU 限额；演练期间暂停正式应用以控制资源。新版或回退均需八个既有服务运行；停止应用之前拒绝发布只恢复入口，不重建容器。克隆迁移失败时重启 Compose 保存的旧功能镜像，正式切换后验收失败时启动兼容回退版。备份保留供排查，不自动恢复数据库覆盖用户数据。

本次现状：运行容器基于 `2350559`，前端已热发布 `5437d77`；Compose 的 `5437d77` 镜像将这份已发布静态资源固化，后端与原运行镜像一致。因此发布与兼容回退以 `5437d77` 为旧功能基线，失败恢复也保留当前已发布的界面，而不退回旧容器启动镜像中的静态文件。

## 回退

直接运行旧镜像的 updatedb 可能生成删除监控表的迁移。使用 [rollback.Dockerfile](rollback.Dockerfile) 从本次实际旧镜像派生：保留原路由、界面和 worker，补齐新模型定义，入口改为仅 `migrate --noinput`。不删除监控表、快照或用户设置，不回滚数据库。

先在克隆环境完成“新版 → 兼容回退版 → 新版”并核对旧记录和新偏好保留。正式回退使用兼容镜像、原环境、原数据卷与密钥；监控 UI 和采集入口不可用，原主机／宝塔任务继续使用兼容的原协议。恢复新版后复用相同数据。若已有未完成的原面板任务，遵循任务模块的等待／待核实流程，不强行停止或重发。
