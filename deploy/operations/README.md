# 运维增强发布工具

这些脚本记录当前演示实例从 `spug-baota:a8af512` 热更新至运维作业版本的流程，并不是通用安装器。固定容器为 `spug`、`spug-db`，固定目录为 `/opt/spug`。在不同实例使用前需核对路径、镜像、服务、数据保全范围及数据库权限。

- `prepare-operations.py <revision> <archive_sha256>`：检查包摘要与路径，构建未来重建镜像及兼容回退镜像；无网络隔离回归、临时 MariaDB 迁移演练及事务验证。复制现网迁移文件作为演练历史，不复制生产配置、凭据或业务行到临时数据库。临时测试容器最多各 256 MiB、单 CPU，完成后移除。
- `apply-operations.py <revision> publish|restore`：容器内固定模块覆盖与原文件回退，校验清单，保留持久卷内运行时迁移。只接受 Python 源码与唯一官方 API 目录 JSON。
- `publish-operations.py <revision>`：要求隔离验证完成且任务空闲；暂停入口、API、WebSocket、面板工作进程和调度器，备份应用数据库及完整数据卷，生成并应用新增迁移，发布静态资产并增加独立运维进程。原生执行与监控进程保持运行；用户主动检测和定时作业须为空闲。

归档需包含 `source/spug_api`、`source/deploy`、本机构建的 `build`、`api-release.json`（源码 SHA-256 清单）、`build/ui-release.json`（静态资产 SHA-256 清单）及上述覆盖器和既有静态发布器。归档顶层为 `operations-<revision前7位>`。准备阶段仅构建和验证；发布阶段才修改现网。

数据库使用应用已有账户备份，仅在数据库容器内暂存 600 权限的客户端配置，完成或出错后清理，不输出口令。成对备份放入带时间戳的私有目录，包含 `database.sql.gz`、`spug-data.tar.gz`、`SHA256SUMS`，另存原 Compose、Supervisor、宿主机脚本及脱敏保全摘要。

失败时尽力恢复各部分，不因服务已经停止而中断整个回退。若新增字段已存在，保留兼容模型，并使未来重建使用 **migrate-only** 的兼容镜像；禁止根据旧模型生成删除字段的迁移。若迁移开始后无法确认实际 schema，则记录未完成回退并保留入口关闭，待数据库恢复后核实；不能假称回退成功。此工具不自动还原数据库、删除新增表或反向迁移。

发布前后核对旧业务字段与密钥摘要、新策略默认为空、原生工作进程 PID、容器 ID、HTTP 和静态版本。上述保全不能替代备份恢复演练；工具不向客户服务器发送测试命令。功能说明见 [运维作业使用指南](../../docs/operations-center-guide.md)。
