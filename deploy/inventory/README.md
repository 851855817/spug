# 网站证书与备份检查台发布工具

本目录针对现有演示实例，从 `spug-baota:2a2eb36` 增量发布。固定容器为 `spug`、`spug-db`，目录为 `/opt/spug`；不是通用安装器。使用前必须确认 Compose 基础镜像、业务空闲和迁移历史。

`prepare-inventory.py <revision> <archive_sha256>` 检查归档路径及摘要，构建新镜像和保留 schema 的兼容回退镜像，在资源受限隔离容器运行测试，并用复制的现网迁移源码在临时 MariaDB 演练新增表。演练不复制生产配置、凭据或业务行。

`publish-inventory.py <revision>` 要求上述演练通过；核对既有业务及运维记录、凭据摘要与空闲状态，暂停入口、API、WebSocket、面板和运维工作进程、调度器，成对备份数据库及数据卷后发布固定模块、增量迁移和静态资源。原生执行、监控和 Redis 进程保持运行。Supervisor 九服务配置不变，不新增后台采集器。

归档结构沿用 [运维发布工具](../operations/README.md) 的清单校验和固定路径覆盖器，顶层为 `inventory-<revision前7位>`。新镜像基于已发布 `2a2eb36`，不重复添加运维进程配置。

保全包括既有运维作业、基线、审计以及宝塔任务策略，不要求历史表为空；有排队或运行中的运维作业拒绝维护，暂停或熔断记录完整保留。新增库存表首轮为空，发布验收不主动请求客户面板。

回退保留新增库存表与模型，回退镜像禁止 `makemigrations/updatedb`，仅运行 `migrate`。若不能确认完整 schema 或任一恢复步骤失败，入口与自动健康恢复保持关闭并记录未完成恢复；不反向迁移，不自动还原数据库或覆盖后续业务记录。配对备份通过结构和摘要检查，不等于完成恢复演练。

`release_safety.py` 必须与发布脚本放在同一目录。数据库导出使用覆盖整个输出读取阶段的 120 秒超时，失败清理临时 SQL 与残缺压缩文件；凭据仅通过容器内私有选项文件提供，并在 finally 删除。`test_*.py` 在无网络临时目录验证导出失败／卡住和恢复失败的入口保护。
