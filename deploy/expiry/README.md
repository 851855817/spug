# 到期管理发布工具

这些工具仅服务当前 `47.104.88.147` 演示实例，固定目录 `/opt/spug`、容器 `spug` 和 `spug-db`，从已发布镜像 `spug-baota:8a64ca1` 增量升级。不是通用安装器，也不适用于另一前版。

1. 完成测试和前端 build，提交工作区后运行 `package-expiry.py`，生成提交编号绑定的源码、静态资源和 SHA-256 清单。包只取 Git 跟踪文件，不带本地配置或密钥。
2. 上传归档，运行 `prepare-expiry.py <revision> <sha256>`。构建新镜像和兼容回退镜像，限资源运行 Linux 回归、真实镜像接线及发布失败保护；复制现网迁移源码到隔离 MariaDB，在已有设置、运维作业、基线、审计和非空库存夹具上演练增量迁移，验证未登记完成的迁移会拒绝自动恢复，并用兼容回退镜像的源码冷启动 Django、运行 migrate，最后验证事务／并发。
3. 规格和质量审查通过后运行 `publish-expiry.py <revision>`。进入维护前复核业务空闲及库存租约；暂停入口、API、WebSocket、面板／运维工作进程和 scheduler，保留原 Redis、原生 worker／monitor。成对备份数据库及完整数据卷，检查摘要及压缩结构后再覆盖固定路径、生成附加迁移、发布 UI。
4. 核对库存及其租约、既有运维记录、用户、角色、主机扩展、配置与密钥摘要，检查新表空态和 GET 不产生记录，再恢复原九服务，验证 HTTP 和 UI revision。未来重建的 Compose 镜像同步更新。

新增每日检查复用原调度器，需同时发布 `apps/schedule/scheduler.py`，不能只覆盖 ops 模块；镜像测试专门检查这条接线。未开启提醒的资产不会自动启用。浏览器验收不修改客户到期日、不调用客户 API、不发送外部消息。

回退保留新增 expiry 模型／表，禁用反向迁移生成，恢复旧 API、UI 和调度逻辑；新表历史不自动删除。API／UI 备份完成后记录原文件摘要，恢复前全量核对；helper 未成功、迁移准备后 schema 缺失或不完整、迁移记录未完成、任一步恢复失败时，入口和自动健康恢复保持关闭，留下脱敏恢复记录。不自动导入旧数据库覆盖发布后业务记录。

使用指南见 [服务器到期管理](../../docs/server-expiry-guide.md)。数据库备份辅助代码复用 `deploy/inventory/release_safety.py`，新发布失败分支由 `test_release.py` 在无 Docker 的临时目录执行验证。
