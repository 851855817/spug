# 升级影响与核验

入口：**批量执行 → 面板任务**。选择“更新 PHP（同分支）”或“面板升级”，生成预检后展开对应面板，在每个项目的“升级核对”查看。历史任务也使用同一视图。

## 执行前核对

“预检版本”是生成这次任务时实际读取的版本，“预计目标”是任务的期望结果，“实际读回”是执行后查询到的版本。尚未查询时显示“尚未读回”，不会用期望版本填充。

PHP 更新的“影响网站”保存本次预检时使用该 PHP 分支的网站，可展开后按网站名称或目录检索，每页 10 个。这里始终显示任务的冻结清单。清单明确为空时显示“本次预检未发现使用该分支的网站”；预检未成功生成清单的旧记录显示“未生成清单”。

例如，准备更新 PHP 7.4 时，展开影响网站，搜索 `/www/wwwroot/customer-a`，确认客户的网站在本次维护范围，再处理对应面板。默认先执行一台，核对结果后继续后续批次。查看清单、检索和翻页不会触发新的面板采集或变更。

PHP 补丁仍由宝塔官方在线脚本决定。9.2 面板的官方稳定通道显示“检查候选”，实际升级版本由官方后台决定；这两个操作都不能将候选版本当作已经安装的版本。

## PHP CLI 模块对照

新生成的 PHP 更新预检在读取版本的同一个 `php_info` 响应中记录目标分支的 CLI 模块名，不额外读取整个 phpinfo，也不保存 ini、环境变量或原始响应。只接收数量、长度和字符受限的清单，并核对必备的 Core／standard 标记。空白、畸形或缺少这些标记的返回不能作为有效清单。

- 执行前显示“已记录 N 个，等待更新后对照”。模块清单无法核实时阻止新更新；预检后模块变化同样要求重新预检。
- 读回后显示未发现缺失，或缺失／新增的数量。“查看扩展变化”列出模块名。
- 唯一关联队列已结束、实际补丁符合预期，但模块缺失或无法对照时，结果保留**待核实**。不会因此重新下发更新或自动安装扩展。
- 仅新增模块且没有原模块缺失时，不会单凭新增阻止结果通过。队列碰撞、请求歧义、运行目录身份变化和版本不符仍按原规则处理。
- 已在执行的历史任务沿用原来的版本核验规则，缺少基线时明确显示“缺少对照记录”。发布前生成但尚未执行的旧预检须重新生成。

例如，更新前有 `pdo_mysql`，更新后补丁正确但该模块不再加载，Spug 显示“缺失 1 个”和待核实。先到目标 PHP 环境排查配置和扩展，再只读核验；不要因版本号正确直接继续整批更新。

对照覆盖 PHP 返回的目标分支 **CLI 模块名清单**。名称相同不证明模块版本或 ABI 相同；它也不证明 PHP-FPM 加载状态、系统默认 CLI、定时任务或网站请求正常。这些范围在核对区明确标记为未核实，需要结合现有 PHP／Web 巡检和业务测试判断。

## 面板升级结果

面板升级核验面板重新连接及版本读回。稳定通道读回版本与检查候选不同，或读回版本尚未适配时，需要人工核实。核对区同时保留候选与实际版本，不替换任务的原始判定。

“详细记录”保留完整的预检、计划、模块对照、下发记录和人工判定。升级核对只是便于阅读这些证据，不增加自动升级、自动修复或自动回滚动作。
