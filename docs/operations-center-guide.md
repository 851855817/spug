# 运维作业与分批执行使用说明

本轮覆盖已选的四项增强：平台自身健康与受控恢复、巡检汇总与失败分类、分批执行与失败熔断、标准作业与配置差异。平台健康的详细说明见 [平台健康指南](platform-health-guide.md)。

## 运维作业

入口：**批量执行 → 运维作业**。第一版仅超级管理员可见，目标来自“主机管理”的 SSH 主机。宝塔列表中尚未添加为 SSH 主机的服务器不能直接用于此入口；宝塔 API 操作仍使用“执行面板任务”。

| 标准作业 | 用途与例子 | 范围与限制 |
| --- | --- | --- |
| Linux 基础巡检 | 检查多台服务器发行版、内核、CPU 数量、负载、可用内存和根分区使用率；例如交接时查出内存不足或磁盘接近满的服务器 | 需要 Linux 与 Python 3；资源数值为采集时点快照，只检查根分区 |
| 宝塔 PHP 配置检查 | 选择 PHP 7.4、8.0–8.5 分支，检查版本、错误显示、PHP 标识、远程包含及固定扩展；例如对比同类客户服务器的 PHP 安全开关 | 使用宝塔标准目录内的 PHP CLI；CLI 与网站实际 PHP-FPM 配置可能不同，不代表网站验证 |
| Web 服务检查 | 检查 Nginx/Apache 可执行文件、版本和本机 TCP 80/443 监听；例如发布前确认 Web 组件是否存在 | 需要 Linux 与 Python 3；本机监听不代表公网可达，可执行文件存在不代表服务正常 |

这些是固定的只读探测，不接受自定义脚本或路径，不安装软件，也不修改配置。探测会使用 SSH 和少量系统资源，沿用现有主机私钥及 SSH 信任方式；远端程序、挂载和 PHP 启动配置仍会影响实际行为。

### 新建与执行

1. 在“标准作业库”核对用途、依赖与限制，再打开“新建作业”。
2. 选择主机或分组。包含子分组，服务器端去重，最终冻结 1–50 台目标。后续修改分组不会向此作业增加主机。
3. 设置每批 1–10 台和批内失败阈值；默认每批 1 台、失败 1 台熔断。后台同一时间只探测一台，“每批台数”控制人工复核范围。
4. 核对弹窗后确认创建并排队。每批结束暂停，查看逐台结果后点击“继续下一批”。
5. 到达失败阈值时熔断；核对后需明确确认才继续尚未执行的目标。原失败或待核实目标不会自动重发。

主机地址、端口、账户、私钥变化或创建者失去超管权限后，尚未执行的检查会被拒绝，应核对后创建新作业。SSH 总时限 60 秒、返回内容上限 64 KiB；连接或认证失败不自动重试。发送后断线、超时或工作进程中断显示“待核实”。关闭连接不能保证远端程序已停止。

“取消未执行项”只阻止尚未下发的目标，已下发检查可能继续返回结果。查看记录、刷新和下载报告均不会重新执行检查。运行时页面每 5 秒读取状态，累计最多 5 分钟；暂停后采用手动刷新，页面轮询本身不发起 SSH。

### 查看结果与失败分类

入口：**批量执行 → 运维作业 → 执行记录 → 查看结果**。创建或打开记录后自动定位到结果区域；可用“只看需处理”查看异常、失败、待核实和未知结果，并展开逐台检查项与处理建议。地址中的 `run_id` 支持刷新恢复到同一作业；本版不随浏览器前进／后退动态切换。

采集成功表示取得了结果，指标仍可能“需关注”或“未知”。不能仅凭“成功”断言服务器健康；展开每台主机查看检查项。可以按采集状态、失败分类筛选。

| 分类 | 建议处理 |
| --- | --- |
| SSH 认证失败 | 核对主机账户、私钥及远端授权 |
| 连接失败 | 核对地址、端口、网络和防火墙 |
| 超时 | 确认主机负载与网络；发送后超时需核实远端状态 |
| 缺少依赖 | 核对 Python 3 或所选宝塔 PHP 分支是否存在 |
| 检查异常 | 返回内容不符合固定格式、超过大小限制或命令异常；不会保存原始输出 |
| 中断待核实 | 核对工作进程及远端状态，再决定是否新建作业 |
| 主机已变化／权限变化 | 核对配置与账户权限，旧作业不会使用变化后的身份继续发送 |

“下载 JSON 报告”保存当前页面快照、逐台状态和结构化检查项。最新读取失败时会标注快照过期；差异结果注明自己的比较时间。报告含主机名称和地址，适合内部归档，不包含私钥、面板密码或完整配置。

## 配置基线与差异

在作业详情选择已成功采集的目标，填写名称并“保存不可变基线”。基线保存该次检查的作业、版本、参数、时间及固定字段；保存后不覆盖、不删除。包含未知字段的基线不会把对应字段变成已知。

例如：先检查一台配置正确的 PHP 7.4 主机，保存为“客户 A PHP74 标准”。随后检查其余 SSH 主机，选择同一基线并比较，可发现 `display_errors` 开启或 cURL 扩展缺失的主机。仅允许相同作业、代码版本和参数比较，PHP 7.4 与 8.2 不混用基线。可搜索名称并翻页查找历史基线。

比较结果是带时间的独立快照，普通“刷新详情”不会重新比较。刷新、搜索或翻页基线，以及确认继续／取消作业会清空旧比较；此前尚未完成的比较响应也会失效。等待旧请求结束后，可重新选择基线并比较。下载只包含当前保留的比较，不能以报告导出时间代替比较时间。

| 差异状态 | 含义 |
| --- | --- |
| 相同 | 两次有效采集的值相同 |
| 变化 | 两次有效采集的值不同 |
| 缺失 | 基线有值，本次未取得有效值 |
| 未知 | 基线未知，或本次采集失败、待核实、尚未完成 |

Linux 资源指标随时间变化，因此差异中也会显示负载、内存和磁盘使用变化。此功能用于检查固定字段偏差，不是任意文件比较，也不提供自动修复或覆盖配置。

## 面板任务的分批保护

入口：**批量执行 → 执行面板任务**。完成既有预检后，新任务默认勾选分批执行，每批 1 个面板、失败阈值 1；可调整为 1–10，或取消勾选沿用原执行方式。历史未启用策略的任务维持原行为。

按冻结目标分批，每批完成后人工继续。按面板统计本次执行失败；预检已有失败项仍展示，但不重复消耗执行失败阈值。文件上传继续遵守逐文件预检、覆盖确认与统一／独立目录规则。

远端处理中或待核实会阻止后续下发，先点击“只读核验”。不确定结果不会自动重发；需要人工判定时填写原因和核验依据，不能把未完成操作直接当作成功。取消仅取消未发送项目，不能撤回已执行的升级、配置或上传。

证书签发和部署可能分为两个阶段。分批模式不会自动发送后续部署阶段；只有只读核验确认可部署、无歧义且未发送过部署请求的当前证书，才可通过专用确认继续部署。该确认不会放行后续服务器；进程中断后需要重新核验与确认。

## 运行维护

PHP 更新和面板升级的影响核对、CLI 模块前后对照及历史任务兼容规则见 [升级影响与核验](upgrade-review-guide.md)。它复用既有冻结任务，不会在查看历史结果时重新采集或执行。

新增独立进程 `spug-ops-worker`，由 Supervisor 管理；平台健康中一并显示。它与原生批量执行及面板任务工作进程独立。停止后仅按平台健康既有规则受控启动，不能用反复重启解决待核实任务。

本功能不创建自动巡检计划，也不向客户服务器自动发起任何升级或配置修改。作业由管理员选择范围并确认后执行；平台健康宿主机定时器只检查平台自身。
