# SSL 列表提醒操作实现计划

目标：从每条有效证书到期提醒直接忽略和恢复，与现有提醒区同步，遵循已确认的账号和周期范围。使用当前分支内联执行，不更改客户来源配置。

- [x] 为 SSL 列表的按账号提醒元数据、缺少有效提醒、周期重置与 GET 无写入增加服务回归，先验证旧实现失败。复用 reminder_rows 的现有过滤，将来源列表作为可选参数复用，避免重复来源查询。
- [x] 前端先验证列表缺少“不再提醒”的失败用例；增加提醒列、请求锁、受控错误和当前账号检查。Reminders 接收外部 revision 与 onChanged，保存成功时两处刷新缓存。回归忽略／恢复、失败、双击、换账号、未开启与无有效提醒。
- [ ] 新增 ssl-reminder-actions 固定 service.py 与两份 UI 的无迁移发布 profile；覆盖空闲门、原摘要、其余完整 API 树保全、post-ssl 检查、原始收据与回退。运行发布合同、完整前端、Linux 隔离后端、生产构建和模拟浏览器验收，独立审查并提交。
- [ ] 按实际线上版本重新检查业务空闲，建立新配对备份后发布；独立核验摘要、SSL 六表与 API 保全、公网和健康，保存文档和 Git 记录并更新草稿 PR。

当前验证：3 项后端新回归先因缺少 reminder 元数据失败后通过；5 项新增前端行为先失败后通过，另补充未生成有效提醒状态用例。前端全量 491 项、ESLint 通过。发布保护 225 项（Windows 跳过1项）通过，新 profile 6 项包含真实双根 API helper 成功/恢复与部分失败回退。独立审查发现的 helper 固定路径缺失已用精确单文件允许修复并复核，未扩大 monitor 前缀。
