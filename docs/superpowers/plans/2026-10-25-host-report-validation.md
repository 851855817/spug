# 宿主机报告一致性修复

夜间计划的现有健康检查缺陷修复，不新增访问权限、远程命令、恢复操作或数据库迁移。基线 `dac7732`，线上应用 `9648bef`；本修复先在隔离环境实现／验证，不能直接复用上次发布器的单 PHP 文件覆盖清单。

## 已复现问题

本机临时 JSON 的 `status=ok`，`checks=[{id:host.http,status:error}]`，现有 `check_host_report()` 返回 ok。函数只校验总状态和数组非空，没有核对内部状态。无需数据库、网络或客户接口即可复现，真实线上文件未修改。

## 最小修复规格

- 保留现有报告大小、时间、新鲜度、脱敏和调用方式。
- `checks` 必须为 1—32 个对象；每项必须有非空且受限的字符串 id（只含 ASCII 字母、数字、点、下划线、连字符，最多 100 字符）和合法状态 `ok/warning/error/unknown`；id 不得重复。不回显报告其他字段。
- 对内部状态采用宿主机生产器既有优先级 `error > warning > unknown > ok` 计算聚合值，总状态必须与其相同；不一致或畸形时返回现有 unknown 和安全提示，不能显示绿色。
- 不限制完整检查项集合，不新增报告签名／格式版本或访问路径。单项的最小兼容报告仍有效；此检查不能证明报告来源可信或检查范围完整。
- 正常生产器输出及 UTC `Z` 时间兼容保持；异常正文、额外敏感字段、任意 id 不进入接口输出。Web 页面其他检查和恢复入口保持原合同。

## 验证与交付

先加入失败回归，确认上述矛盾总状态及畸形／重复检查失败，再实现。测试所有合法聚合组合、时间边界、UTC `Z` 和实际宿主机生产器生成的完整报告（注入假执行器，无 Docker／网络）。运行独立平台健康测试、后端目标回归及 CI，完成规格与质量审查，更新指南和夜间进度后提交现有分支／草稿 PR。
