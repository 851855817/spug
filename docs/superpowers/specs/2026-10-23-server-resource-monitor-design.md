# 服务器监控卡片设计

依据：用户提供的卡片页面；用户确认同时覆盖主机管理和宝塔面板管理，同一台服务器尽量合并；两处列表增加开启／关闭监控，默认关闭，仅开启后展示详情。

## 页面与开关

- 在“监控中心”下新增“服务器监控”，原有检测任务保留为“监控任务”。
- 主机列表、宝塔面板列表增加“监控”开关。现有记录和新记录默认关闭，状态保存在服务端，刷新或重新登录不丢失。
- 关闭的来源不采集、不返回缓存详情；监控页只显示当前用户有权访问且已开启的来源。关闭后下一次列表刷新移除卡片。
- 开关沿用来源编辑权限，SSH 来源还校验主机分组权限。只读账户能看有权访问的已开启卡片，不能操作开关。

## 卡片布局

卡片显示名称、IP（可隐藏）、来源、分组、采集状态和更新时间；正文显示三项负载、上下行速率、CPU 核数和占用、内存已用／总量、磁盘已用／总量及比例。CPU／内存／磁盘用进度条展示，多个磁盘可展开。根据窗口宽度自动排列 1～4 列。

顶部提供分组、来源、状态筛选，名称／IP 搜索、刷新和自动刷新开关。默认 60 秒采集，可选 30／60／300 秒；页面隐藏、离开或关闭自动刷新时停止发送采集请求。单台采集失败只影响自身卡片，旧数据明确标识过期，缺失指标显示“—”，不以 0 冒充正常。

## 两种来源与合并

- 宝塔使用已保存 API 配置，通过固定的系统查询接口读取资源，不重新填写密钥。
- 主机使用已保存 SSH 凭据执行固定、有超时和输出上限的 Linux 只读采集，不安装常驻 agent。
- 同一台服务器可将宝塔记录关联到主机记录，合并为一张卡片；只有开启且有权限的来源参与采集和展示。优先宝塔 API，符合条件时使用已开启 SSH 来源作为后备。
- 相同 IP 只作为关联建议，用户确认后保存绑定。共享公网 IP、NAT、域名解析和不同 SSH 端口可能对应不同机器，不能据此直接认定同一台。
- API 未配置、主机未验证、认证失败或不支持的系统分别显示可理解的状态；不会自动安装依赖、修改面板或执行运维任务。

## 资源与验证

只为可见的已开启卡片采样，服务端共享短期缓存、同目标锁和全局最多 2 台并发，前端错开采集，上轮未结束不重叠；失败采用退避。多人打开共享缓存，手动刷新也不绕过最短 30 秒采样间隔。关闭开关和配置变更后使旧快照失效。第一版提供实时概览，不新增历史曲线或报警策略。用户于 2026-10-23 批准本方案及以上负载控制。

验证覆盖默认关闭、开关持久化、关闭后拒绝采集、权限与分组隔离、关联与取消关联、启用来源优先级、数值与单位归一化、超时与缓存、异步刷新不覆盖新状态，以及响应式卡片。生产验证保持用户现有开关默认关闭，不为演示自行开启客户监控。
