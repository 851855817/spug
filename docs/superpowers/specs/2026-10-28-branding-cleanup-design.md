# KOps 日常界面品牌整理

用户要求暂不售卖平台，先隐藏日常界面的 Spug 相关展示。沿用已授权的 KOps · 云枢名称及按协议修改的要求。本次更换产品文案，不宣称完全原创，不改变开源许可。

## 展示

- 登录页、页脚及关于页面的常驻文字仅显示 KOps · 云枢及 K 维护。原作者、基于 Spug 的来源、修改日期、AGPL、无担保、再分发权利、完整许可和免费精确源码链接集中在已有且无需登录的“开源许可与源码”弹窗；入口继续显著可见。
- 关于页面展示当前 KOps 应用提交和运行环境；内核版本采用中性标签。删除上游官网推广、更新日志入口和自动上游更新请求，避免把上游升级误作二开升级。
- 宝塔 API 提示、主机导入、任务计划、发布流程与 LDAP、密钥说明改为“平台”“本平台”或 KOps，LDAP 例子改用 example.com。英文翻译同步。
- 基本设置的真实外部服务仍使用原调用凭据和端点；服务商与凭据获取说明折叠到主动打开的详情，避免冒充 K 的自有服务或隐藏配置依赖。不会清空已有配置。

## 不变项

源文件版权头、根许可证、对应源码、技术变量 SPUG_*、数据键、进程名、目录和服务端接口保持兼容。真实第三方服务在需要配置时保留身份。没有用户/角色/权限/数据库修改，没有客户连接和任务。

## 验证与发布

修改现有品牌测试，确保登录前后均可打开法律弹窗且初始常驻文字不含上游品牌；关于页面仅请求本地信息、版本不假冒自研内核。普通文案不为每个字符串写镜像测试，使用搜索与浏览器验收。

新 `branding-cleanup-ui` 精确 UI 白名单（16 个运行文件）以实际 diff 为准，仅静态构建，不覆盖任何 API。强制完整 API 镜像树保全、当前版本核对、业务空闲、成对备份、原始收据和四入口兼容恢复。继续现有分支、草稿 PR #4，不合并主分支；不修改生产配色和客户数据。
