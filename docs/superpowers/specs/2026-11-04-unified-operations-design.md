# 运维作业与面板任务统一入口

## 用户目标

用户认为“运维作业”和“面板任务”入口重叠，要求整理到一起。目标是减少寻找任务及结果的成本，沿用现有分支 `feature/operations-reliability` 与草稿 PR #4。

## 现状与方案选择

两者都具备选择服务器、创建任务、查看执行记录和逐台结果。实际执行不同：运维作业通过 SSH 执行固定 Linux、PHP、Web 只读检查；面板任务通过宝塔 API 处理网站、软件、PHP、证书、文件上传等操作。

推荐统一页面与导航，按任务类型使用现有流程。另一个方案是将两套后台和记录合并成统一模型，需要迁移历史记录、重做状态机及任务授权，对减少入口没有额外收益。本次采用前者，不进行后台合并。

## 页面与导航

- 用户最新明确要求将运维作业增加到面板任务：左栏“批量执行”下只显示“面板任务”，地址沿用 `/exec/panel`。
- 页面顶部选择“主机巡检”或“宝塔操作”，下方使用一致的“新建任务”和“执行记录”标签。主机巡检的作业说明在该类型内提供。
- 主机巡检包括 Linux 基础巡检、PHP 配置检查、Web 服务检查；宝塔操作保留现有支持的操作、上传和受控预检流程。
- 历史结果仍按原类型读取：主机巡检保持正常／异常、原因与检查数据；宝塔操作保持原目标、预检、确认、逐项结果和只读核验。
- 进入页面、切换类型或查看记录只读取相应后台数据，不自动创建、预检或执行任务。
- 切换类型或离开当前宝塔任务时销毁继续／部署／取消确认框；旧确认回调不得下发请求，提交前重新核对对应动作权限。

## 链接与权限

- `/exec/panel` 默认打开“宝塔操作”，原 SSL 预填参数保持有效；`?type=inspection` 打开“主机巡检”。已有 `/exec/operations?run_id=...` 自动转入统一页面并打开原结果。
- 网站证书、SSL 监控等页面已使用 `/exec/panel`，无需改动；任务计划中嵌入的预检表单和结果预览继续复用原组件。
- 统一导航的可见条件为超级管理员或已有 `exec.panel.view` 权限。主机巡检继续仅超级管理员可用；宝塔创建、执行和查看继续分别使用原权限。
- 无权访问的类型不显示、不请求对应 API；URL 参数不能授予权限。既有岗位角色不添加权限。
- 同组导航拖拽偏好过滤掉已隐藏的旧入口，保留其他菜单顺序。

## 范围与验证

本次只调整前端组合、路由、文案与使用说明，不修改数据库、后台状态机、任务调度或客户配置。原生“执行任务”“模板管理”“文件分发”和“任务计划”不纳入此次合并。

验证覆盖：单一可见入口；有权限的类型切换；仅宝塔查看权限的账号不会请求巡检接口；SSL 预填及旧巡检结果链接；创建与执行确认仍有效；查看历史不会发送任务；窄屏及全站主题；原任务计划嵌入表单与结果预览回归。全部使用模拟接口，不执行客户操作。

发布前重新核实现网版本、业务空闲和当前 SSL 迁移兼容边界，配对备份并验证准确前端变更清单；不使用尚未适配新 SSL 基线的旧发布流程。提交代码、测试与文档，更新原草稿 PR，不合并主分支。
