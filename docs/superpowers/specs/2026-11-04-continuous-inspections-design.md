# 主机巡检点击即执行、遇错继续

用户明确要求取消截图中的每批台数与熔断阈值：点击“确认执行”直接开始检查，某台失败展示详细原因并继续其他主机。按此已授权行为实现，不再增加确认步骤。

## 行为

- 新建主机巡检移除批次／阈值输入和二次弹窗。按钮一次点击创建后台巡检，直接打开逐台结果；重复点击被 pending 锁阻止。
- 保持最多 50 台、递归分组去重、冻结身份、每次实际下发前重新授权。Worker 逐台处理，单台失败／超时／结果未知均继续下一台，直到全部结束；可以取消尚未下发项，不重试已下发项。
- 旧手动分批历史保留原流程，不自动放行旧暂停任务。API 新增 `execution_mode: continuous` 显式选择新策略，旧调用默认 manual。新模式禁止携带手动批次参数。
- 无数据库变更：使用既有批次字段表达一次覆盖最大 50 台、失败上限 51 的连续策略；这些值不属于旧 API 允许的 1–10 策略，`is_continuous` 统一辨别，API 返回明确的 execution_mode。内部常量有名称，UI 不展示这些实现参数。
- 断线恢复将已 running 项标为未知，不重发；新连续作业有剩余项则重新排队，旧手动作业仍熔断。用户取消优先，权限撤销后不得连接客户。

## 错误

记录可核实的阶段／错误：DNS 解析、TCP 拒绝或网络不可达、SSH 密钥解析、认证、握手、通道、命令返回码、依赖缺失、输出超限、非 JSON、无有效指标和超时。仅保存受控诊断与数值返回码，不能把原始异常、stderr、命令、配置或凭据写入结果。PHP 缺失提示具体受校验的版本路径。未知原因明确未知，提供核查建议，不编造根因。

结果直接显示异常原因和建议，仍提供具体检查数据。历史记录没有细诊断时保持原 message 并使用分类建议。宝塔操作、安装／升级／续签流程不在本次修改范围。

## 验证与发布

模拟连续成功／失败／未知／恢复／取消，断言每台最多一次、无需人工继续、旧策略不变。模拟 DNS、SSH、输出及返回码并证明不泄露注入凭据；前端验证无输入、无二次确认、双击不重复、错误原因和结果可见。

沿用原分支及草稿 PR。固定发布 profile 仅允许 service、worker、runner 三个既有 API 模块和 RunForm／RunDetail 两处 UI；全树校验其余 API。使用隔离数据与客户接口模拟，重新核对现网、业务空闲和 SSL 六表保全，备份后发布，不实际执行客户巡检。
