# SSL 列表排除旧结果

用户明确要求不再显示旧缓存，承接上一轮提出的来源失效结果收起方案。本次采用统一排除，不增加历史记录入口、不要求用户逐条隐藏。

SSL 列表在个人隐藏、分页、状态筛选和统计之前，排除 `certificate_view` 判定为 stale 的证书：来源关闭、授权失效、配置变化、巡检失败、超过有效期或证书与来源摘要不一致。默认列表和“查看已隐藏”口径相同。旧 `state=stale` 查询兼容返回空结果，页面不再提供该筛选项。

启用来源的新鲜正常、即将到期、已过期、证书错误或未配置结果继续展示；个人隐藏与提醒保持独立。来源重新成功巡检后，新的有效结果自动进入列表。启用来源的采集失败原因在页面单独简短展示，不再拿旧证书日期充当本次检查结果。关闭来源不产生失败提示。

历史快照和任务留在数据库以支持任务追溯，接口不向证书列表返回这些旧结果。GET 不写库、不连接客户，不删除文件、任务、证书或个人偏好，不变更来源和提醒开关。

前端把“刷新缓存”改成“刷新列表”，说明仅展示有效巡检结果；保留“立即巡检”的显式远程操作。旧行响应防御性过滤，禁止通过旧结果创建续签。

发布采用新固定配置 `ssl-current-results`，运行变更恰好为既有 `apps/monitor/ssl/service.py` 和 `spug_web/src/pages/ssl-monitor/index.js`。旧 service 摘要必须存在，完整 API 树与 PHP、健康、用户数据保全；复用隔离回归、post-ssl、空闲门、新配对备份及原始收据兼容回退。无迁移、模型、权限或客户操作变更。
