# KOps · 云枢：商务配色扩展

用户要求在已上线的五套配色之外增加更高级的配色，沿用管理员设置、全账号统一生效的机制。现有授权涵盖增加配色和发布验证，不再改变设置流程。

## 视觉方向

采用深浅兼备的低饱和方案：曜石金（obsidian-gold）、深海青（midnight-teal）、月影紫（moonlit-violet）三套深色；暖瓷白（porcelain）、雾松绿（pine-mist）、香槟砂（champagne）三套浅色。相比只替换按钮颜色，统一背景、表面、侧栏、边框、文字和交互强调色，更能满足用户的全站配色需求；不引入纹理和大面积渐变，保持运维数据易读。

保留原有五套模板及标识。模板卡片用微型后台轮廓呈现导航、表面与强调色，同时保留名称、说明和当前使用标记。选择只预览，应用后才保存。文字与链接及按钮文字对比度至少 4.5:1，正常、警告、异常继续用绿色、橙色、红色与文字说明。

## 实现与边界

前后端固定白名单同步扩展。保持版本、并发修订校验、管理员限制和公共只读接口，不接受任意 CSS，不新增数据库结构或客户操作。

AntD 深色 Less 继续独立编译后低优先级限定作用域；在编译产物中将已知的底色与品牌色转为带原值后备的 CSS 变量，让新增深色的弹窗、选择器、日期选择和输入框跟随模板。原夜间配色的派生色使用原值后备，不更换状态色或终端内容色。新增浅色为暖白/冷白表面，对主要 AntD 控件的表面补齐变量覆盖。

生产发布使用新的 `refined-palettes` 窄补丁：仅覆盖已存在的 appearance.py 和固定五个 UI 文件（presets.js、config-overrides.js、theme.less、AppearanceSetting.js、appearance.module.css）。原始 site-appearance 首次发布规则保持严格。新补丁要求真实旧模块哈希、完整镜像其余 API 不变、成对备份及可验证回退；保留当前生效配色，不在生产替用户切换。
