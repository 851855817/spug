# 服务器到期管理

入口：**主机管理**页面右上角的**到期管理**，地址 `/host/expiry`。仅活跃超级管理员可访问。

这页解决“服务器分布在不同云厂商，忘记续费或不知道由谁跟进”的问题。管理对象来自已经添加的 SSH 主机和宝塔面板，无需重新添加密钥。列表读取 Spug 本地记录，打开、筛选和刷新均不连接客户服务器或云厂商。

## 找出需要处理的服务器

顶部显示资产总数、已过期、7 天内、30 天内、未登记和日期无效。7／30 天均包含今天，且不包含已经过期的资产，30 天内包含 7 天内，不能将这两项相加。统计保留当前来源、分组、负责人、关键字及跟进条件，到期状态筛选只影响列表。

例如先选“30 天内到期”，再按负责人筛选，可以列出某位同事本月需要跟进的续费。按宝塔分组筛选也能找到已与主机合并的资产。表头分割线支持拖动调整列宽，双击恢复默认。

今天到期显示“今天到期”，明天才算已过期。平台采用 `Asia/Shanghai` 日期。没有日期显示“未登记”，无法识别的历史值显示“日期无效”；这两类均不表示服务器正常或已续费。

## 日期来源与人工登记

点击“编辑”选择日期来源：

- **使用主机已有记录**：复用主机扩展信息中的到期日。这些旧字段可能由人工填写或云导入生成，页面不将其称作实时云 API 结果。独立宝塔没有主机记录，此选项表示未登记。
- **人工登记**：填写 `YYYY-MM-DD` 格式的日期，独立保存；之后的云同步不会覆盖它。列表同时展示主机原记录供对照。

还可指定负责人、填写备注、标为“待跟进／已联系”，或明确标记“无需到期管理”。指派负责人不会赋予对方查看该资产的权限。负责人停用后会显示“已停用”，应重新指派。

多人同时编辑或关联／原日期发生变化时，旧页面保存会被拒绝。关闭编辑框、刷新列表后重新核对，避免覆盖别人的修改。

## 登记续费

向云厂商确认续费完成后，点击“登记续费”，填写新的到期日和备注。新日期必须晚于平台今天，也必须晚于原有效日期。保存后使用人工日期，跟进状态回到待跟进，负责人及提醒开关保留。

这只是记录您核对过的结果，Spug 不会向云厂商付费或自动续费，也不证明云厂商已经收款。点“已联系”或将提醒标为已读都不会把真实过期状态变成正常。

“记录”可查看操作者、时间和变更前后值。历史按资产保留，新的续费登记不会删除旧提醒与记录。

## 同一台主机和多个宝塔

到期管理复用监控关联设置中**人工确认的主机关联**，不按相同 IP 猜测合并，且不要求监控开启。一台主机关联两个宝塔后仍是一项到期资产，使用主机侧的到期日、负责人和提醒开关。

宝塔曾经单独登记的到期信息会暂停生效；取消关联后恢复。关联和取消前的确认框会提示此影响。这个操作不改变监控开关，也不会启动客户采集。

## 管理员站内提醒

每项资产的提醒**默认关闭**。编辑中开启并确认后，已有 Spug 调度器每天 **09:00（Asia/Shanghai）**检查本地日期，并在本页“站内提醒”页签产生记录。

| 剩余时间 | 提醒阶段 |
| --- | --- |
| 8—30 天 | 30 天提醒 |
| 2—7 天 | 7 天提醒 |
| 0—1 天 | 1 天／今天提醒 |
| 已过期 | 过期提醒 |

同一资产、同一到期日、同一阶段只生成一次。首次开启时若只剩 5 天，仅生成 7 天阶段，不补发其他旧阶段。新到期日进入新的提醒周期。无需管理、关闭提醒、无有效日期的资产不会产生新提醒。

关闭后重新开启，若到期日和阶段都没变，会继续使用原提醒，已读状态也保留，不会因此生成重复提醒。登记新的到期日后，旧提醒及其已读状态保留，新日期进入提醒范围时生成新提醒。未读数量包含尚未阅读的历史提醒；选择“仅当前有效提醒”只筛选列表。

每位管理员的已读状态独立保存。可筛选“仅未读”或“仅当前有效提醒”；日期、阶段、关联或提醒设置改变后，原提醒保留并显示“已过时”。“刷新提醒”只读现有记录，不提前触发每日检查。

提醒仅出现在到期管理页，**不会发送邮件、短信、微信或机器人消息**，也不使用顶部全局通知铃铛。非管理员负责人需要由管理员线下联系。此版没有站外触达承诺。

页面展示最近成功检查时间。调度器停止时不会生成新提醒，超过检查时限会提示关注；到“系统管理 → 平台健康”核对调度服务。平台离线期间不能提醒，重启后恢复每日调度，在下一次检查时生成当前阶段。
