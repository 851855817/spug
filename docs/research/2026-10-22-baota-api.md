整理日期：2026-10-22。本文是静态研究记录，不表示接口已经接入 Spug 或通过客户面板实测。

## 签名、认证与输出

官方 API 使用表单编码。签名为 `request_token = MD5(request_time + MD5(api_key))`，`request_time` 为秒级 Unix 时间戳字符串。网页登录账户密码不能代替 API 密钥；需要开启 API 并将 Spug 出口 IP 加入白名单。

13.1.0 的 `panel/class/common.py` 的 get_sk 实现检查开启状态、请求签名和来源 IP；连续认证失败存在临时封禁机制，因此连接测试不能无限重试。

官方概览通称 POST，但 Docker 的部分说明页使用 GET，包括会修改状态的操作。方法和是否变更必须由操作注册表逐项声明，不能按 GET 推断只读。

查询接口也可能返回数据库密码、Cookie 或证书私钥。适配器只输出允许的字段，不直接记录整个 JSON 或异常响应。

## 八类操作的协议依据

### 面板升级

现代入口：`POST /system?action=upgrade_panel`，实现位于两个更新包的 `panel/class/system.py:1408`。

- 不传 force 参数时，返回 local/cloud/upgrade 信息；此查询也会更新宝塔自己的缓存或下载检查元数据，不会进入该函数的软件更新分支。
- 只要 force 参数存在就进入执行分支，且必须提供 version。因此 `force=false` 也不能作为查询请求。
- 执行分支启动后台升级脚本并返回已启动，需轮询恢复状态、升级日志和最终版本。
- 同包 `get_upgrade_log` 位于 system.py:1634。日志不是唯一完成依据。

旧入口：`POST /ajax?action=UpdatePanel`，11.7.0 位于 ajax.py:912，13.1.0 位于 ajax.py:921。该函数可能因更新服务返回 force=true 或本地 autoUpdate.pl 而进入更新；请求携带 check 并不能保证只检查。禁止用于批量任务的无软件变更预检，也不能直接照搬旧版 PDF 的参数理解。

### 添加网站

现行官方文档：https://docs.bt.cn/api/site/actions/index.md 的 AddSite。

`POST /site?action=AddSite`，主要参数为 webname JSON（domain/domainlist/count）、path、type、version、port、type_id、ps。PHP 站点使用 type=PHP 及面板已安装版本，纯静态 type 留空、version=00。FTP 和数据库属于可选联建，第一版不隐含执行。

siteStatus=true 是初步结果，仍需读回该面板内的网站 ID、域名绑定、目录及 PHP 类型。不能在不同面板间复用网站 ID。

### 防跨站

现行官方文档同上：multiple_basedir、GetDirUserINI。

`POST /site?action=multiple_basedir`，site_ids 为该面板的网站 ID JSON 数组；stat=open/close。该功能是 PHP open_basedir 目录限制，不是表单 CSRF 设置。返回 succeed/errors 后，使用 GetDirUserINI 的 id、path 读回 userini。

### 伪静态

现行官方文档同上：GetRewriteList / GetRewriteLists、SetRewriteTel、SetRewriteLists。

- GetRewriteList 根据 siteName 返回该面板可用模板。
- SetRewriteTel 的 name/data 是保存自定义模板，不能直接视为已给目标网站生效。
- 文档对 SetRewriteLists 的参数描述与 11.7.0/13.1.0 官方实现不符：sites 必须包含该面板网站的 id 和 file，rewrite_data 是完整规则文本，不是模板名。
- GetRewriteLists 使用 site_ids JSON 数组及 site_type=PHP，返回 site_rewrites 和 template_rewrites，但会创建缺失规则文件；GetFileBody 也会创建路径中含 `rewrite` 的缺失文件。任务资源、预检和只读核验禁用这两个接口，不将它们视作缓存例外。规则目标从已核实网站身份及服务器类型构造固定路径，浏览器不能提交 file。
- 当前适配器使用单数 GetRewriteList 获取模板名称；使用 `/files?action=get_file_hash` 的 md5+sha1 只读摘要确认目标存在、冻结原状态、阻止内容漂移并核验保存结果。目标规则文件缺失时预检行失败，不创建空文件。模板内容通过固定 `/download` GET 获取，禁止 `/files?action=DownloadFile`（后者将远程内容写入服务器）。模板下载只允许 nginx/apache 下的合法模板名称，64 KiB 上限，并核对读取前后摘要；实际 UTF-8 文本冻结后统一 CRLF 为 LF。
- 已核对两版本 `/download`：先 `comm.local → check_login → get_sk` 校验，`get_input` 同时读取 query 和 form。因此 filename 位于 query，`request_time/request_token` 放在 GET form body，不进入 URL；服务端普通访问日志可能记录公开文件名，不含凭据。仅接受 200、`application/octet-stream` 和匹配的 attachment 文件名，拒绝 JSON 错误和重定向，沿用固定 CA/指纹、总请求时限、大小限制及错误脱敏。ACME fullchain 的读取也使用固定域名路径下载（128 KiB），不使用可能创建文件的 GetFileBody，不读取私钥或向 UI 返回 PEM。
- GetSiteRunPath 在网站根目录缺失时会创建目录；GetDirUserINI、Apache GetRewriteList 也会间接调用它。适配器在这些调用前使用只读 get_file_attribute 核对服务端网站根路径、is_dir=true、is_link=false；路径先经字符和规范校验，缺失或无法核实即失败。该前置避免自然缺失根目录的创建，不声称能原子防止管理员恰在两次面板请求之间删除目录；宝塔当前协议没有提供这种原子只读运行目录接口。
- 模板规则从经过归属验证的模板路径读取；自定义内容直接作为规则文本应用，不必先保存全局模板。SetRewriteLists 对现有文件备份，写入后检查 Web 配置，失败时恢复，成功后重载。必须逐网站调用并读回核实，避免共享临时备份文件造成跨网站干扰。
- 两版本 SetRewriteLists 均在调用 serviceReload 之前设置子项 status=true，并忽略 serviceReload 返回值。因此 status=true 加规则文件摘要一致，只能证明配置已保存，不能证明 Web 服务实际加载。适配器返回“待核实”，证据为 configuration_saved=true、runtime_verified=false；只读读回不能将其提升为成功。显式 status=false 优先判失败，并核对回滚摘要；即使回滚失败留下目标文本也不能报成功。Apache 非根运行目录存在官方路径拼接缺陷，当前拒绝该分支。

### SSL 申请和续签

现行官方文档：https://docs.bt.cn/api/acme/actions/index.md ，配合网站 GetSSL。

- apply_cert_api：id、domains JSON、auth_type、auth_to。HTTP 使用网站实际验证目录；不能只假设站点目录一定等于运行目录。
- renew_cert：关联订单 index，不能空 index，避免触发对全局订单的处理。13.1.0 的 acme_v2.py:3047 同时接受参数对象或字符串订单号，并会在部分分支写日志后返回空值，不能只看 HTTP200 或布尔 status。
- SetCertToSite：index、siteName，用于部署至所选网站并开启 SSL。13.1.0 位于 acme_v2.py:3605，11.7.0 位于 :3037。
- 完成判断包括证书确实签发、部署到指定网站、证书域名/到期日/指纹正确。pending、签发成功但部署失败、已部署但外部路由无法访问应分别描述。
- API 返回可能含 private_key，禁止写入日志或返回浏览器。

2026-10-22 源码质量复核补充：11.7.0、13.1.0 的 apply/renew 会经 download_cert → save_cert → sub_all_cert 自动同步证书，不能将第一请求描述为“只签发、不部署”。sub_all_cert 扫描 `/www/server/panel/vhost/cert`、`/www/server/panel/vhost/ssl`、`/www/server/panel` 的直接子目录，替换 SAN 集合相同、签发者条件匹配且有效期不晚于新证书的证书及私钥。范围可能包括未选择网站、孤立证书目录和面板自身 TLS；随后调用 Web 服务重载，没有禁止同步的请求开关。renew_cert_to 还会临时关闭并尝试恢复 HTTP 跳转 HTTPS 设置。

适配器第一阶段的持久化意图必须覆盖签发/续签及上述自动同步，预检计划固定 `ssl_scope.policy=baota_acme_panel_sync_v1`、`required_acknowledgements=['ssl_panel_sync']`。任务服务在下发前持久化并核对该确认，浏览器不能传入缩小范围或跳过确认的适配器参数。预检通过 GetSSL 最多读取 200 个已登记网站，保存相同 SAN 的公开证书摘要并在初次下发前复核漂移；清单始终标为不完整，不能据此承诺遗漏的网站、孤立目录或面板 TLS 不受影响。不会为此读取私钥或枚举任意文件。

若初次请求已自动更新选定网站，读回新证书指纹后无需另发 SetCertToSite；成功结果只证明选定网站公开证书配置读回，不证明实际 TLS 连接，也不声称整个同步范围均已验证。证据明确记录 selected_site_configuration_verified=true、live_tls_verified=false、panel_sync_outcome_verified=false。只有目标网站尚未更新时，才返回 next_action=deploy，要求另存持久化意图后调用 SetCertToSite。若面板 TLS 被自动替换而导致固定指纹校验失败，任务保留待核实及面板锁，不能自动接受新指纹、放宽信任或重复申请/部署。

DNS 差异：现行说明将 apply_dns_auth 描述为调用已配置的 DNS API，但 13.1.0 的 acme_v2.py:2744 标注为 DNS 手动验证，调用 apply_cert([], auth_type='dns', auth_to='dns', index=...)。自动 DNS 的实际 auth_to 结构和凭据引用必须另行按版本联调，不能直接照搬该说明。第一版选择 HTTP 文件验证；泛域名不适用 HTTP 验证。

### 安装软件

现行 107 页参考未直接列出该协议；依据官方更新包实现：

- 路由 `/plugin` 在 BTPanel/__init__.py 注册 install_plugin、get_soft_find、get_soft_list 等 action。
- `POST /plugin?action=install_plugin`：11.7.0 的 panelPlugin.py:904；13.1.0 的 :905。使用 sName、version、min_version、type，按面板实际返回版本选择。
- 实现包含 CPU、内存、系统、互斥、依赖和授权检查，不得强制绕过。
- 核心软件通常异步写入 tasks 表；部分插件同步安装或使用独立升级流程。返回 status=true/msg_id 不是统一的远端任务 ID，也不是成功安装证明。

软件和版本必须来自经过校验的面板列表，后台再校验标识和格式；这些参数最终可能被面板写入 shell 命令，不接受浏览器传入任意软件名、版本字符串或命令。

13.1.0 的 get_soft_list 返回 `list` 为带分页信息的对象，实际条目在 `list.data`，不是顶层数组。顶层还可能有 skey 等敏感字段，禁止原样返回。系统版本读取使用 GetSystemTotal.version；GetSystemVersion 在该版本经路由传参会因形参不匹配返回 500，不能用于连接检查。

### 安装 PHP 扩展

官方更新包：`POST /ajax?action=GetPHPConfig` 查询指定 PHP 分支的扩展（version 为该分支内部标识，如 74）。11.7.0 的 ajax.py:1058；13.1.0 的 :1067。

安装使用 `POST /files?action=InstallSoft`，name 为该 PHP 分支支持的扩展名、version 为 PHP 分支、type 为安装方式；11.7.0 的 files.py:3839；13.1.0 的 :3882。该实现写入软件安装队列并可能同步 PHP CLI 配置，不能只看扩展目录或误判为升级 PHP 主程序。

读回验证该分支的扩展安装状态和实际加载状态；面板存在 OpenLiteSpeed 专用分支，需要单独适配后启用，不能混用 Nginx/Apache 的 PHP 路径。

### 卸载软件

`POST /plugin?action=uninstall_plugin`：11.7.0 的 panelPlugin.py:1140；13.1.0 的 :1141。软件商店卸载与 `/files?action=UninstallSoft` 的扩展卸载不能混淆。保留面板的依赖与安全限制；例如 MySQL 存在数据库时有拒绝卸载分支。

卸载可能是同步脚本操作；请求中断后不自动重发。读回安装状态并核实影响，不能仅依据“接口返回成功”。

## 任务监控差异

软件安装的 tasks 表与 `/task` 后台任务的 task_list 表不同。源码分别可见 files.py/panelPlugin.py 和 panelTask.py，不能混为同一个队列。

`/files?action=GetTaskSpeed` 读取软件安装队列且包含触发队列等副作用，不适合当作纯粹无影响的连接探测；必须在版本适配器的已下发监控阶段使用。远端可能同时有人手动操作，需记录下发前后的目标、队列快照及可用的关联标识，再以实际安装状态验证。

## 实现验收前的必要验证

本次只完成静态协议核对，没有连接、修改或升级任何客户宝塔面板。实现时需用隔离测试面板验证这两个版本，并按用户实际面板版本追加适配记录。不能将“找到官方源码”标成“已支持全部 Linux 版本”。

真实任务应保留参数快照、远端关联、最终状态和脱敏证据。所有变更在预检预览后由用户提交；测试和部署控制台本身不触发客户变更。
