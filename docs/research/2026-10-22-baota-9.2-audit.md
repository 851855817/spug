# 宝塔 Linux 9.2.0 协议兼容审计

> 历史审计：以下结论记录适配前的阻断依据。后续已分别实现 [9.2 稳定通道升级](2026-10-22-upgrade92.md)、[SSL 主配置核验](2026-10-22-ssl92.md)、[PHP 同分支更新](2026-10-22-php-update.md)及核心软件类型限制、CLI 证据校验。当前操作边界以这些记录和使用指南为准；未将源码分析或夹具测试称为客户真实变更测试。

日期：2026-10-22。结论：**不能仅把 9.2.0 加入 `SUPPORTED_VERSIONS`。保持现有版本门禁。** 升级目标契约不兼容；SSL 证书读回存在实质差异；“只读 API”还存在此前未覆盖的面板端初始化和持久化写入。

本次只读取本地官方源码、ZIP 成员及现有适配器/测试，没有导入或执行宝塔包代码，没有连接服务器或客户面板，没有修改业务代码，没有运行真实 9.2.0 操作。用户实际面板报告 9.2.0 仅是版本信息，不是九项操作验证证据。

## 八类九项操作的判定

“协议可复用”只表示选定请求字段/返回形状相符，仍受后述预检副作用、版本专属回归和运行证据限制；不表示现在开放生产执行。

| 类别 / 操作码 | 判定 | 9.2.0 源码契约与现有适配器的关系 |
|---|---|---|
| 面板升级 `panel_upgrade` | **必须阻断** | `/system upgrade_panel` 无 `force` 返回检查结果；有 `force` 时忽略请求的 `version`，运行追随云端版本的修复脚本。检查返回的 `cloud` 也不是可直接假定存在 `OfficialVersion/OfficialVersionLatest` 的 v3 协议。见下一节。 |
| 添加网站 `site_add` | 请求协议可复用，需回归 | `/site AddSite` 接受 JSON `webname.domain/domainlist/count`、`path/version/port/ps/ftp/sql`；检查 PHP、域名、端口、目录并生成配置（`9.2/panelSite.py:639-744`）。应用发送 DNS 名、ASCII 数据目录、明确端口，避开后续版本新增的 IPv6/站名重命名差异。`GetPHPVersion` 的 `[{version,status,...}]` 形状一致（`:3944-3988`），但该读接口可创建 Nginx 配置。创建本身还会初始化 `.user.ini`，不能把操作预览描述为只写网站数据库。 |

## 必须先解决的差异

### 升级无法冻结目标版本

`9.2/system.py:1270-1297` 调用旧 `get_panel_version`；`:1274` 仅判断 **是否有 `force` 字段**，不是其真假。完全省略字段才是检查；`force=false/0/空串` 也进入变更分支。`:1294` 固定执行：

```text
script/upgrade_panel.py repair_panel
```

没有把请求的 `version` 传给脚本。ZIP `panel/script/upgrade_panel.py:475-488` 的 `get_panel_info(v)` 仅识别 `lts`；其他值查询当前云端发布。`:500-526` 在后台启动后重新查询版本并下载，`:609-613` 在没有第二参数时传入 `None`。因此在预检后云端变化时，实际目标可变化；即使允许客户端发 `version`，9.2 路由也忽略它。脚本的 shell 回退还会运行 `update6.sh`（`:519-522`）。

对照：`11.7/system.py:1544-1560` 明确要求 `get.version` 并传给 `upgrade_panel_optimized.py upgrade_panel <version>`；11.7 ZIP 的旧 `upgrade_panel.py:531-549` 也已有显式版本分支。不能把后续版本的 `cloud.OfficialVersion` 结构套到 9.2 的旧云端响应上：包中只显示 `cloud=json.loads(res)`（`9.2/system.py:1282`），本次没有查询当前云端。

应用 `operations/upgrade.py:25-38,48-57` 的“不带 force 检查、冻结候选目标、下发指定 version”只能保留前一条为 9.2 已确认。**9.2 升级必须单独禁用**，直到存在经审查且可证明实际安装所选版本的专属协议；不能依靠事后读回检测来弥补此前已安装错误版本的风险。

### 9.2 SSL 读回不能证明网站配置使用该证书

`9.2/panelSite.py:2653-2663` 优先读取 `/www/server/panel/vhost/cert/<site>/fullchain.pem`，仅当公私钥都不存在时退到 `/etc/letsencrypt/live/<site>`；`:2686-2699` 只是读取网站配置并检查是否含 `ssl_certificate` / `SSLCertificateFile` 文本。若网站实际指向自定义证书路径，固定目录中的新证书和 `status=true` 可以同时存在，而服务配置仍使用另一张证书。

对照 `13.1/panelSite.py:2628-2644` 会解析证书和私钥指令的实际路径。应用 `operations/certificates.py:99-110,335-338` 现在信任 `GetSSL` 的 `csr`，随后在 `:177-179` 标成 `selected_site_configuration_verified=true`。9.2 必须增加受限的网站配置/证书路径核对，或在不能核实时保持阻断/待核实，不能沿用这一成功证据。不能通过任意文件读接口或浏览器提供路径绕过限制。

`GetSSL` 另会把未知证书导入 SSL 管理数据库（`9.2/panelSite.py:2714-2725`，ZIP `panel/class/ssl_manage.py:275-283` 调用 `save_by_data`）。**这是既有问题，13.1 同样有该行为**（`13.1/panelSite.py:2678-2689`），不是 9.2 专属回归。它还会读取并在响应中带上私钥；现有传输内部解析、只保留公开字段的约束仍必须保留。

## 可保留的协议与必须覆盖的边界

### 授权、路由、系统和资源

- `9.2/BTPanel:612-679,760-773,1045-1090,1235-1281,1299-1306,1368-1388` 注册了当前所有需要的 action，并调用 `comm.local()`。`common.py:228-294` 校验 API 开关、白名单和 `md5(request_time + api_config.token)`；ZIP `panel/class/panelApi.py:239-253` 将 token 的 MD5 写入配置，应用 `client.py:223-232` 的时间戳/双 MD5 表单签名形状相符。未使用客户密钥验证。
- `/download` 是 GET（`BTPanel:1428-1432`），同样走 `comm.local`；`get_input:2703-2726` 合并 query 与 form，所以签名可保留在 GET body。`:1460-1480` 缺失文件返回错误，不会创建，成功 `application/octet-stream`/attachment 与应用的严格响应校验相符。HTTP 中间层是否接受 GET body 尚无 9.2 实测。
- `GetSystemTotal` 返回 `version/system/cpuNum/memTotal`（`9.2/system.py:255-270`），方法体与 11.7/13.1 相同。继续避免直接走不接受参数的 `GetSystemVersion`（`:301`）。`GetConcifInfo.webserver` 仍可提取（`:25-60`），其原始对象可能含数据库敏感信息，禁止透传。
- `getData` 仍返回 `data` 数组，sites 会补 `php_version`（`9.2/data.py:454-460,504-519`）。分页、重复 ID、总量、Linux 识别和服务器端字段约束可保留。源包审查不保证云端软件目录类型和约束永远不变。

### 文件属性、根目录与伪静态

- `9.2/files.py:4580-4619` 返回 `name/path/is_dir/is_link`，缺失先拒绝；`:4496-4509` 的 hash 仅以 `rb` 打开、返回 `md5/sha1`，和较新版本相关方法相同。`:4553-4567` 的 `lsattr` 拼接路径仍要求应用校验面板返回的站点路径；不能仅校验浏览器输入。
- `GetSiteRunPath` 会在根目录缺失时 `os.makedirs`（`9.2/panelSite.py:5793-5794`）。`GetDirUserINI→GetRunPath→GetSiteRunPath`（`:4136,1668-1678`）同样可触发。保留 `resources.require_site_root` 的规范路径、存在目录、非符号链接及身份字段守卫；跨请求删除竞态依然存在，该守卫也不能消除构造器的其他初始化。
- 单数 `GetRewriteList` 方法的模板列表为字符串数组（`9.2/panelSite.py:5120-5168`）。复数 `GetRewriteLists:7103-7108,7122-7129` 创建缺失文件/目录；`GetFileBody:2268-2271` 创建名字含 rewrite 的缺失文件。现有禁止这两种 getter 读取规则的设计应保留。
- Apache 复数 resolver 的 `_path + runPath + '.htaccess'`（`:7126`）对 `/public` 产生同级 `public.htaccess`；现有只允许 `runPath='/'` 的约束应保留。模板下载前后摘要、UTF-8/换行与删除竞态校验仍有必要。
- `SetRewriteLists:7142-7209` 接受每站 `id/name/file` 和完整 `rewrite_data`，先备份/写文件/检查配置，失败恢复；`:7199` 设置成功后 `:7207` 不检查 `serviceReload()` 返回值。继续将文件保存读回和 Web 运行生效分开，不能把 hash 相等提升为运行成功。

### SSL 申请、续签、同步、部署阶段

- `acme_v2.py:1825-1891` 接受当前 HTTP 申请字段；`:418-462` 保存 domains/auth_type/auth_to 和订单索引；`get_orders:259-267` 返回带 index 的列表。成功签发返回证书/私钥等，不保证返回 index，继续只提取合法关联标识，必要时用新订单差集关联，不保存原始响应。
- `download_cert:1134-1163` 把状态设为 `valid`，路径 `vhost/letsencrypt/<首域名>`，调用 `save_cert`；`:1166-1207` 保存公开证书/私钥并调用 `sub_all_cert`。固定 fullchain 下载范围可复用，不读取订单指定的任意路径。
- `sub_all_cert:1289-1340` 扫描 `vhost/cert`、`vhost/ssl`、面板目录的直接子目录，按 SAN 集合、兼容 issuer、到期时间资格替换证书和私钥（含面板 TLS），并重载 Web。与 11.7/13.1 对应方法的有效代码一致。现有固定 `baota_acme_panel_sync_v1`、同步范围确认和始终不完整的登记网站清单应保留；不能缩小为所选网站。
- `renew_cert_to:2161-2206` 临时关闭并尝试恢复 HTTP→HTTPS；`renew_cert:2212-2225` 明确选定 index，`:2288-2296` 可能缩减域名后复用 index。旧版本缺少现代算法/CA 切换和失败订单状态恢复逻辑，现有仅 HTTP/Let's Encrypt 的范围不可扩大。
- `SetCertToSite:2475-2482` 经 exclude hash 交给 `panelSSL`；ZIP `panel/class/panelSSL.py:1124-1154` 删除旧链/旧续签文件、保存 canonical 公私钥并调用 `SetSSLConf`，不是纯复制证书。继续持久化首次申请/续签及自动同步的意图；只有读回表明未部署才进入独立 deploy 意图，每次 dispatch 最多一个变更；断连、TLS pin 改变或关联漂移都不重发。真实 TLS 和其他同步位置仍不应标成已验证。

### 软件队列和 PHP 加载证据

- `get_soft_list:1880-1940` 的目录位于 `list.data`；`get_soft_find:2307-2367` 返回单项并可把依赖转换成未满足分组。只提取允许字段、不透传云端 key 的策略可保留。
- 核心软件任务名 `安装[<name>-<major>]`、status `0`，`msg_id` 是消息标识（`panelPlugin.py:1092-1112`），不是任务 ID；可能先额外入队“安装必要环境库”（`:4143-4205`）。扩展为 `安装[<name>-<phpbranch>]`（`files.py:3658-3668`）。保留精确括号目标、下发前 ID 集合、唯一候选和实际版本/加载读回；不能把队列终结或 `status=true` 当安装成功。
- `GetTaskSpeed` 明确写 `/tmp/panelTask.pl`，某些异常还重置队列状态（`files.py:3768-3799`）；当前直接读 `tasks` 表的设计应保留，预检及只读核验不能改用它。
- `ajax.py:1985-2033` 用 PHP CLI `-c <ini> class/php_info.php`；ZIP `panel/class/php_info.php:5-6` 通过 `get_loaded_extensions()` 采集。响应是 `phpinfo.modules` 空格串，现有解析 fallback 可复用；失败可返回空模块，不能假设空串是有效运行证据。
