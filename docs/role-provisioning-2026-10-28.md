# 五个岗位角色创建记录

按用户明确要求，已在现有 KOps · 云枢实例创建五个实际角色。入口：**系统管理 → 角色管理**。

| 角色 | 角色 ID | 功能权限数 |
| --- | --- | --- |
| 只读审计 | 3 | 12 |
| 值班运维 | 4 | 16 |
| 网站运维 | 5 | 7 |
| 发布工程师 | 6 | 12 |
| 运维主管 | 7 | 39 |

功能权限直接由已发布提交 `9f749a877703aa593b9e95718f2520c775571057` 中的 `presets.js` 与 `codes.js` 生成，执行相同的 `buildPresetPermissions` 逻辑，逐项核对展开后的权限码与模板原始权限列表一致。角色备注包含模板用途和权限边界。详细说明见 [岗位模板指南](role-presets-guide.md)。

创建前只读确认没有这五个同名角色。通过现有角色管理视图的 POST 与 PATCH，在单个数据库事务中完成创建及功能权限保存；事务内核对原角色完整内容、全部账号和角色关联保持不变。另起进程调用角色管理视图 GET，确认每个名称恰好一条、权限结构与模板完全一致。

五个角色均未关联员工，SSH 主机组及发布应用、环境授权均为空。需要在角色管理中分配资源范围，再在账户管理中为员工选择角色。网站运维仍仅能创建面板预检，运维主管仍不是超级管理员。

本次仅创建用户要求的角色数据，无代码发布、服务重启或数据库迁移，没有执行客户服务器操作。
