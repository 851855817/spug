# Spug 平台功能说明与使用手册

适用对象：管理多台云服务器、客户网站和宝塔 Linux 面板的负责人、运维人员与发布人员。

初稿日期：2026 年 10 月 23 日，初稿源码基线 `6b5b3c8`。2026 年 10 月 26 日补核对运维作业、网站证书、备份检查、到期管理、平台健康与升级核验说明；对应演示应用版本为 `4b051b1`，详见[发布记录](releases/2026-10-26-operations-comparison.md)。本文提供操作方法与示例，不表示已对所有客户服务器执行过这些操作。菜单是否可见取决于账户权限，通知、LDAP、Git 发布等能力还需要各自配置。

这套平台把服务器登录、批量脚本、宝塔操作、代码发布、巡检和告警集中在一个后台。最适合解决“服务器多、客户多、重复操作多、逐台登录容易漏”的问题。建议先把服务器和面板分组，再用少量目标验证流程，最后按组处理。

本文示例使用“客户甲”“客户乙”、`example.com` 和文档保留 IP，均需替换为实际信息。文中“本机”须结合功能理解：浏览器选择文件时是你的电脑，任务计划或发布脚本中的本机通常是 Spug 所在服务器或容器。

### 两种管理通道

**SSH 通道**面向服务器操作系统。主机管理、执行任务、巡检模板、原生文件分发、部分发布和监控任务使用它。需要从 Spug 执行环境连接服务器 SSH 端口，并完成密钥授权。

**宝塔 API 通道**面向宝塔 Linux 面板。二开的面板任务、宝塔文件上传和宝塔资源采集使用它。需要面板 API 密钥、正确的 API 地址、出口 IP 白名单和可用的证书信任设置。

同一台服务器可以同时登记在两边，但两种授权不互通。只填宝塔地址、账户和密码，不能替代 API 授权；只登记宝塔，也不会自动变成可执行 SSH 模板的主机。

### 新增运维入口怎么选

下面五个入口目前仅超级管理员可用；到期管理是主机管理页面右上角的按钮。

| 入口与详细说明 | 工作情境与操作边界 |
| --- | --- |
| [运维作业](operations-center-guide.md) | 交接或维护前，对 SSH 主机执行固定 Linux／PHP／Web 检查，分批复核，再与已保存基线比较。结果在“执行记录 → 查看结果”；查看、刷新和下载不会重新执行。采集成功仍需展开检查项判断异常。 |
| [网站与证书、备份检查台](panel-inventory-guide.md) | 安排续签或追查备份漏跑时，先筛选各面板的本地库存，再按需主动采集。打开页面、筛选和刷新缓存均不连接客户面板；失败保留上次成功快照并标旧。证书登记不等于公网实际证书，备份登记不等于文件完整或能恢复。 |
| [服务器到期管理](server-expiry-guide.md) | 汇总 SSH 主机与人工确认关联的宝塔资产，登记到期日、负责人、跟进及已完成的续费。只读 Spug 本地数据，不查询云厂商或付款。提醒默认关闭，开启后每天 09:00 产生管理员站内提醒，不发邮件／短信。 |
| [平台健康](platform-health-guide.md) | 后台打不开或作业不动时，检查 Spug 自身的数据库、队列、进程、磁盘和宿主机报告。页面不自动轮询，下载不发起新检查；只允许确认后启动指定的已停止服务。后台不可访问时使用指南中的宿主机工具。 |

例如，同一客户的网站证书快到期，先在“网站与证书”核对采集时间、网站与日期；“填写续签任务”只预填面板任务，仍须读取资源、冻结预检和确认。PHP 更新的影响网站、版本与 CLI 模块前后对照，另见[升级影响与核验](upgrade-review-guide.md)。

## 02 第一次使用的推荐顺序

1. 管理员在“系统管理 → 角色管理”安排权限，再给工作人员创建账户。日常人员使用各自账户，便于区分操作记录。
2. 在主机和宝塔列表建立分组，例如“客户甲 → 生产”“客户甲 → 测试”“内部工具”。分组名称要能让执行人员判断影响范围。
3. 有 SSH 权限的服务器加入“主机管理”，完成连接验证；需要宝塔自动化的面板加入“宝塔面板管理”，补充 API 后测试连接。
4. 先选一台测试主机运行“磁盘空间与 Inode”之类的只读巡检，检查返回结果和执行通道。
5. 对希望查看资源的记录开启监控；需要离开页面后继续告警的业务，另外创建“监控任务”。
6. 做网站、软件或证书变更前，先核对备份和目标，再生成面板任务预检，逐台确认后执行。

**完成标准：**你能够明确指出某台服务器属于哪个客户、使用哪种通道、连接是否正常，以及执行结果应在哪里查看。

### 平台访问地址

目前使用的 `http://127.0.0.1:18080/` 是通过本机 SSH 转发访问的入口。它只表示当前电脑上的转发地址，不是客户宝塔的 API 地址，也不是可直接发给别人使用的公网演示站。

如果该入口打不开，先检查本机转发连接，再检查 Spug 服务和服务器网络。它与客户网站是否正常是两件事，不应仅凭这个地址打不开就判断所有客户站点宕机。

## 03 工作台与 Dashboard

### 工作台

**用途与场景：**把团队公告和常用链接集中到登录后的工作页面，解决维护通知散落在聊天记录、常用系统入口难找的问题。

**如何使用：**管理员可新建、修改、排序和删除公告；重要公告可以设为弹窗提醒。同一时间仅设置一条强提醒公告。便捷导航可以配置名称、说明、图标和多个链接。普通用户阅读公告并打开链接。

**例子：**发布“今晚 22 点维护客户甲网站”的公告，同时在便捷导航中放置域名服务商、工单系统和项目仓库。当前“待办事项”区域为空列表实现，不能把它当成已经接入审批或工单的待办系统。

### Dashboard

**用途与场景：**查看平台内应用、SSH 主机、任务计划和监控任务的数量，以及报警趋势和发布申请 Top20，用于了解运维与发布活动。

**如何使用：**进入 Dashboard 查看统计卡片；发布排行可按今日、本周、本月或自定义日期筛选，点击相关统计入口进入明细页面。

**例子：**负责人查看本周哪个应用发布最频繁，或近期报警是否集中出现。这里的“主机”是原生主机统计，不应当作已合并的宝塔资产总数；实时 CPU 和内存请进入“服务器监控”。

## 04 主机管理

### 主机登记与分组

**解决的问题：**统一保存服务器名称、SSH 地址、端口、用户、分组和备注，避免在多个终端或表格里找连接信息。适合云服务器集中运维、按客户选择批量执行对象。

**操作：**建立分组 → 添加主机 → 填名称、连接地址、SSH 端口与用户 → 根据需要上传独立私钥 → 保存并验证。默认使用平台全局密钥，独立密钥优先；编辑时未替换的密钥保持原值。

**首次授权：**默认密钥尚未获准时，可按界面提示输入该 SSH 用户密码，用于首次配置密钥认证；该密码不作为常驻登录密码保存。上传独立密钥时，应确保公钥已在目标用户下授权。

**例子：**把客户甲两台生产服务器放在“客户甲 → 生产”，用户设为有相应权限的运维账户。之后执行任务时选这个组，不必重复录入 IP。服务器实际能执行哪些命令，仍由该 SSH 用户的系统权限决定。

### 批量导入与验证

**用途：**一次录入多台已有资产，并检查平台能否连接。适合首次接管一批服务器或新增一批云主机。

**操作：**使用列表的批量导入，先下载并按模板填写，再选分组导入；阿里云和腾讯云导入入口需要对应云厂商访问授权。导入后逐台查看验证结果，失败的检查地址、端口、密钥和网络规则。

**例子：**接管 20 台服务器，先批量导入，再处理其中 3 台未验证的记录。导入成功仅表示登记完成，不能替代 SSH 连通性验证。

### 主机详情与 Web 终端

**用途：**查看单台主机资料、连接状态，并通过浏览器进入 SSH 终端；终端内可进行授权范围内的排查和文件上传下载。适合单机故障定位和临时维护。

**操作：**从主机列表打开详情或从顶栏终端入口选择主机，确认名称和地址后连接。终端设置可调整字体大小、字体和主题。

主机详情还可维护实例 ID、操作系统、CPU、内存、磁盘、公网与内网 IP、计费方式、创建和到期时间等扩展信息，适合资产盘点和续费核对；登记的到期日不代表平台已经代为续费。云导入记录可按页面入口同步资料。

**例子：**批量巡检发现某台磁盘占用高，进入这台主机的终端进一步查看目录占用。终端命令直接作用于服务器，没有面板任务的冻结预检流程，输入前要自行核对对象。

**终端文件管理：**可浏览远端目录，按权限上传、下载或删除文件，适合单机临时取文件和维护。先确认当前路径再操作，删除不是移动到电脑回收站；给多台同时发文件应使用文件分发或宝塔上传。

### 监控开关和详情图标

**用途：**决定该记录是否参与资源监控，并在列表就近查看它的资源卡片。新增记录默认关闭。

**操作：**在“监控”列打开开关；点击折线图监控图标，弹出对应服务器信息。关闭状态点击图标会提示“未开启监控”。关掉开关后不再作为该来源的启用监控对象。

**例子：**只监控 5 台关键生产服务器，其他登记主机保留管理功能，避免所有资产都参与资源采集。若同机还有已启用的宝塔来源，需按关联情况确认剩余来源的状态。

## 05 宝塔面板管理

### 集中保存客户面板

**用途：**按客户或用途保存宝塔登录入口、账户和密码，配合分组、搜索、编辑、删除及打开面板。适合有大量客户宝塔、但不想逐个翻找入口的情况。

**操作：**建立分组 → 添加面板 → 填名称、完整登录地址、账户和密码 → 根据需要填写 API 连接 → 保存。列表显示 IP 或主机名，隐藏完整面板地址和账户，编辑时可调整资料。登录密码加密保存，不会通过普通编辑接口返回明文。

**例子：**客户甲登录地址为 `http://192.0.2.10:8888/abc123`。完整地址保存在记录中，列表只露出主机部分。“打开面板”进入其登录页，不等于免密自动登录。

### 配置 API 与连接测试

**解决的问题：**让后续任务直接使用已保存授权，不在每次创建任务时重复填写客户 API。

1. 在客户宝塔设置中开启 API，取得 API 密钥。
2. 在宝塔 API 白名单填入 Spug 服务器对该客户面板发请求时的实际出口 IP。有 NAT、代理或多出口时，以实际来源为准。
3. 在 Spug 面板记录的“API 连接”填写密钥；基础地址通常自动从登录地址提取。
4. HTTPS 使用可信证书；自签证书按界面配置专用 CA 或核对并固定 SHA-256 指纹。
5. 保存后在列表执行“测试连接”，检查检测时间、实际版本和返回状态。

**地址例子：**登录入口 `http://192.0.2.10:8888/abc123`，直连 API 通常使用 `http://192.0.2.10:8888`。安全入口路径不是普通 API 的前缀；反向代理若实际使用路径前缀，才按部署情况手动调整。浏览器的 `127.0.0.1` 不应填写为客户 API 白名单来源。

**密钥维护：**编辑已有记录时，API 密钥留空表示保留原值，不表示清空；手动修改过的 API 地址也不会随登录地址自动变化，应自行核对。

### 版本信息与适配范围

**用途：**识别当前实际面板版本，避免拿旧记录判断升级状态。本版适配宝塔 Linux 9.2.0、11.7.0、13.1.0，各操作仍需通过自己的资源和协议检查。

**例子：**宝塔已升级，Spug 列表仍显示以前的版本时，先点击“测试连接”。成功测试和任务资源读取会更新保存版本及检测时间；仅刷新列表不会额外轮询所有客户面板。

**权限边界：**当前宝塔分组用于整理和选择，不提供按客户分组的数据隔离。不能仅靠把客户分在不同组，就向外部客户开放同一个后台。记录存在任务历史或锁保护时，删除可能受限。

### 监控与 SSH 关联

宝塔列表同样提供默认关闭的监控开关和详情图标。需要 API 连接可用才能从面板采集资源。若和 SSH 主机确为同一台服务器，在服务器监控的关联设置中确认关系后合并展示；同 IP 只作为建议，不能自动认定同机。

## 06 批量执行任务与模板管理

### 执行任务

**用途：**一次把相同 Shell 或 Python 内容送到多台 SSH 主机，逐台查看输出。适合临时查询、巡检、经审核的系统维护，解决一台台登录复制命令的问题。

**操作：**进入“批量执行 → 执行任务” → 选择脚本语言 → 编写内容或载入模板 → 填写参数 → 选择主机 → 核对数量和分组 → 执行 → 查看逐台控制台和历史记录。历史可回填内容，回填后仍需再次确认本次目标。

**例子：**选择 10 台 Linux 主机，执行 `df -h /`，一次看各台根分区用量。结果只说明该命令查到的情况，不代表磁盘、挂载点和整机都健康。

**条件：**Python 脚本需要目标主机具备相应解释器；软件和系统命令也必须存在。任意脚本会以所配置 SSH 用户身份运行，修改命令不会因保存到 Spug 就自动变成安全操作。

### 模板管理

**用途：**把反复使用的脚本保存成标准动作，统一名称、分类、语言、内容、参数、默认主机和备注。适合把团队经验变为可重复执行的运维工具。

**操作：**新建模板 → 选分类与语言 → 填脚本和参数说明 → 保存；执行时在“执行任务”载入模板，检查参数及默认主机后再运行。保存、编辑或导入模板本身不会执行脚本。

**例子：**建立“生产磁盘巡检”，运维人员不必每次重写查询命令。默认主机是选择便利功能，不是固定不可改的授权范围；每次执行仍应核对。

### 已整理的二十个巡检模板

平台已整理 8 个原生 Shell 模板和 12 个 Python 模板。它们参考公开命令文档及检查思路后独立实现，进行了固定命令、参数校验、输出限制和时限处理；这不等于任何环境下都不存在风险。

| 模板组 | 具体内容 | 数量 |
| --- | --- | --- |
| Shell 通用巡检 | 系统版本与运行时间、CPU 负载与内存、磁盘空间与 Inode、进程资源 Top20、TCP 与 UDP 监听端口、失败的系统服务 | 6 |
| Shell PHP 检查 | 宝塔 PHP CLI 版本、PHP-FPM 进程 | 2 |
| Python 通用巡检 | 同上六项通用检查的 Python 实现 | 6 |
| Python PHP 检查 | CLI 版本、安全相关配置、已配置扩展、PHP-FPM 进程 | 4 |
| Python 网站检查 | HTTPS 可用性、TLS 证书到期 | 2 |

**参数例子：**PHP_VERSION 填 `7.4` 或 `74` 检查 7.4，填 `all` 检查支持范围内的全部分支。当前固定覆盖 5.4 至 5.6、7.0 至 7.4、8.0 至 8.5；自定义或符号链接安装目录可能不适用。

**怎么选择：**目标没有 Python 3.8 及以上时，先用 Shell 模板；Shell 需要 Linux、Bash、GNU coreutils 的 timeout 等以及对应查询命令，模板不会自动安装依赖。PHP 安全配置与扩展声明检查、网站检查当前在 Python 模板中。

**如何读结果：**“已配置扩展”只说明配置文件有声明，不证明已经成功加载；PHP CLI 版本不代表站点实际 FPM 版本；进程快照不证明网站健康。Python 网站检查仅检查公网域名的 HTTPS 443，不跟随跳转，证书不足 30 天会提示。检查失败、依赖缺失和超时应按“检查未完成”处理，不能当作无异常。

## 07 原生文件分发

**入口：**批量执行 → 文件分发。使用 SSH，与下一章的宝塔上传是两套功能。

**用途与场景：**从电脑上传文件，或从一个已纳管主机读取源路径，再统一发给多个 SSH 目标。适合分发配置样本、静态资源包、运维文件，不必先配置宝塔 API。

**操作：**选电脑文件或源主机及源路径 → 填统一目标绝对路径 → 选目标主机 → 核对 → 开始分发 → 查看逐台结果及历史。源主机取文件需要其路径存在、权限可读；目标需要可写。

**例子：**把一个经过确认的 `maintenance.html` 发到 5 台测试主机的 `/tmp/site-check/`。原生分发依赖 rsync，缺失时应先另行准备。目录源及路径结尾会影响最终落点，首次先用临时目录和一台主机确认。

**结果边界：**本模块的 rsync 输出与传输状态，不等于宝塔上传模块的逐文件读回 SHA-256 核验；它也没有宝塔版“公共目录加每台覆盖目录”的同一套表单和冻结流程。文件可能覆盖同名内容，原文件要另行备份。前端提示分发历史按账户保留最近 10 条，应及时留存重要结果。

## 08 宝塔批量面板任务

### 通用流程

**入口：**批量执行 → 面板任务。用途是向已授权的客户宝塔发布结构化操作，无需为每个面板手写 API 调用。

1. 选择面板或分组；分组包含子分组，重复面板自动去重。
2. 选择操作，展开各面板，读取它自己的网站、软件或扩展，填对应参数。
3. 点击“生成冻结预检”，检查当前状态、拟做动作、依赖和影响范围。
4. 完成该操作要求的确认，再点击“确认并开始执行”。
5. 在执行记录查看成功、失败、已符合、跳过和待核实项目；需要时先做只读核验。

预检保存的是本次计划。之后修改表单不会改变已经冻结的任务，需要重新生成预检。预检不会下发所选变更动作，但宝塔部分查询本身可能更新缓存、初始化配置或运行内部维护逻辑。

默认每次最多 50 个面板、常规操作最多 200 个子项目，同时处理 2 台面板；同一面板的变更串行。上传文件有独立上限。后台任务开始后，关闭网页不影响其继续执行，但应返回记录确认最终结果。

### 宝塔面板升级

**解决的问题：**多台客户宝塔需要维护版本，避免逐台点升级。适合已安排维护窗口、完成备份与兼容性检查的面板更新。

**操作：**选择“面板升级” → 逐台读取实际版本和候选 → 按版本选适配的官方目标或通道 → 预检 → 确认 → 查看升级后版本与结果。

**例子：**对客户甲两台面板先升级测试机，再处理生产机。9.2 使用官方稳定通道，无法锁定精确最终版本；候选变化可能阻止下发，实际结果偏离候选会保留待核实。升级可能使面板短暂不可用；这更新的是客户宝塔，不是 Spug 平台本身。

### 更新 PHP 同分支

**解决的问题：**给多台服务器已有 PHP 分支安装官方提供的更新，减少重复编译操作。

**操作：**选择“更新 PHP（同分支）” → 选每台已安装且有更新的分支 → 查看实际 CLI 当前版本、预计补丁目标和使用该分支的网站 → 确认可能重启 PHP → 执行并核验。

**例子：**更新多台 PHP 7.4，完成后仍是 7.4.x，不会自动切换为 PHP 8.2，也不改变站点绑定的分支。实际补丁由官方在线脚本决定，Spug 不能把该脚本的结果锁成任意指定补丁。只有队列及实际版本等条件满足才报告成功；这仍不等于验证 FPM 或网站业务全部正常。

**升级核对：**项目直接显示预检、期望和实际读回版本。影响网站可展开检索、分页核对；新 PHP 更新记录 CLI 模块清单并对照新增／缺失，版本达到预期但模块缺失或无法核实时保留待核实。旧任务缺少对照基线会明确提示。操作和核验边界见 [升级影响与核验说明](upgrade-review-guide.md)。

### 添加网站

**用途与场景：**把一批新网站按面板批量创建，解决新客户或多站点初始化时重复填表的问题。

**操作：**选择“添加网站” → 在结构化表格中按行指定目标面板、域名、目录、端口及已安装 PHP 或纯静态 → 可使用批量粘贴 → 预检冲突 → 确认创建 → 核对各面板结果。

**例子：**在测试面板创建 `demo.example.com`，目录设为 `/www/wwwroot/demo.example.com`，使用已安装的 PHP 8.2。创建网站只建立相应站点配置，不代表域名已经解析、代码已经上传、数据库已经准备或业务已经上线。

### 配置防跨站

**用途：**控制所选网站的 open_basedir 等适配设置，限制 PHP 文件访问范围。适合多站点共享服务器时统一开启或核对。

**操作：**选择“防跨站” → 选各面板网站或本次全部网站 → 选开启或关闭 → 查看预检影响 → 执行。选择“全部网站”应再次检查本次快照包含的站点。

**例子：**为同一客户的普通 PHP 站点开启防跨站。某些程序会读取站点目录之外的共享文件，开启后应验证业务；防跨站不是容器隔离，也不能替代权限控制或程序漏洞修复。

### 配置伪静态

**用途与场景：**统一部署站点 URL 重写规则，适用于 WordPress 等程序路由、静态路径优化或已确认的规则修正。

**操作：**选择“伪静态” → 选网站和 Nginx 或 Apache → 选模板、自定义规则或清空 → 核对原内容及变更 → 预检并执行。不同 Web 服务的语法不能混用。

**例子：**给几台 Nginx 上的新 WordPress 站点应用已验证的规则。保存规则文件不等于 Web 服务已成功加载；接口无法证明加载状态时任务会保留待核实，需要管理员核对实际配置和访问结果后填写依据。

### 申请或续签 SSL 证书

**用途：**集中处理网站免费证书申请和同订单续签，降低漏续签导致浏览器报错的概率。网站选项会显示到期日期、已过期或未配置；读取异常时显示未知，选中后的详情提供北京时间。

**申请步骤：**先确认域名解析到目标服务器、HTTP 80 端口及验证路径可访问 → 选“申请 SSL” → 逐台选网站和域名 → 预检 → 确认签发及同步影响 → 执行 → 查看证书配置和到期日，再实际访问验证。

**续签步骤：**选“续签 SSL” → 选有可续签订单的网站 → 核对证书、域名和订单 → 预检并确认 → 查看结果。未配置证书的网站应走申请流程，不能把续签当作所有网站的首次申请。

**例子：**网站证书将在两周后到期，为对应网站发起续签。本版支持 HTTP 文件验证的单次操作，不支持 DNS 验证或通配符证书，也不会因创建了一个任务就永久自动续签。CA 的签发限制仍适用。

**实际影响：**宝塔可能把同域名证书同步到同面板内其他网站、孤立副本或面板自身 HTTPS，并可能重载 Web 服务。所选网站清单不是完整同步白名单。任务核对证书配置，不等于已经验证所有位置的真实 TLS 握手。

### 安装软件

**解决的问题：**在多台客户宝塔的软件商店中批量安装所需运行环境。安装的是各台客户面板的软件，不是给 Spug 安装插件。

**操作：**选“安装软件” → 读取每台软件目录 → 选名称、版本和安装方式 → 核对已装状态和依赖 → 预检后执行。目前开放已适配的官方免费异步核心软件，目录里能查到的项目不一定都允许执行。

**例子：**为几台新服务器安装其面板实际提供的 PHP 分支。各面板可安装版本可能不同，不能把甲面板的版本编号照搬给乙面板。“加入安装队列”不代表安装完成，也不会隐含更新已有软件或切换网站 PHP。

### 安装 PHP 扩展

**用途：**批量补齐某个 PHP 分支的扩展，解决程序上线提示缺少扩展时逐台操作的问题。

**操作：**选“安装 PHP 扩展” → 选每台已安装 PHP 分支 → 从该分支实际支持的列表选扩展 → 检查预检和重启影响 → 执行 → 在程序实际使用的 PHP 环境中验证。

**例子：**为使用 PHP 7.4 的站点安装面板提供的 Redis 扩展。给 PHP 8.2 安装同名扩展不会自动满足 PHP 7.4 站点；CLI 和 FPM 的加载配置也需要分别理解。

### 卸载软件

**用途与场景：**清理已确认不用的组件或退役测试环境。先弄清软件由哪些站点或服务使用，避免因释放空间而破坏业务。

**操作：**选“卸载软件” → 选择实际已装软件 → 阅读预检列出的依赖影响 → 确认备份和业务迁移 → 执行并检查结果。被阻挡时先处理依赖，不能把阻挡视作需要绕开的提示。

**例子：**测试环境已经迁移到新 PHP 分支，确认没有站点继续使用旧分支后再考虑卸载。数据库等有业务数据的软件不适合作为随意试用的卸载例子；Spug 不提供此类业务数据的自动恢复承诺。

### 上传文件或目录

**用途：**不依赖 SSH，直接通过已授权宝塔给多个网站发文件；可给每台使用不同的目标目录。适合静态资源、前端产物和经过确认的网站文件同步。

1. 选目标面板或分组，再选“上传文件 / 目录”。
2. 从电脑选多个文件或一个目录。目录会保留自身名称与内部层级，空目录不会上传。
3. 填公共目标绝对目录；有差异的面板填单独目录。
4. 点击“上传并生成冻结预检”，文件先暂存在 Spug。
5. 核对每台最终目录、目录来源、预计新增及覆盖数，勾选覆盖确认后开始。
6. 查看逐文件结果；读回大小和 SHA-256 都一致才显示成功。

**目录优先级例子：**公共目录 `/www/wwwroot/site`，客户乙单独设 `/www/wwwroot/shop`。上传目录里的 `dist/css/app.css` 分别落在 `/www/wwwroot/site/dist/css/app.css` 和 `/www/wwwroot/shop/dist/css/app.css`。单独目录留空才继承公共目录；单独目录无效时阻止预检，不会偷偷回退。公共目录可空，但每台都必须有合法单独目录。

**覆盖规则：**只覆盖本次同名文件，不删除目标中的其他文件，不自动解压压缩包。符号链接、文件和目录同名等冲突会阻止对应项目。覆盖不是原子替换，上传期间可能短暂不完整；没有远端自动回滚，需要回退时使用自己保留的原文件。

| 当前默认限制 | 上限或规则 |
| --- | --- |
| 单文件 | 20 MiB |
| 每批文件内容 | 200 MiB |
| 每批文件数 | 1000 个 |
| 面板数与并发 | 最多 50 台 同时 2 台 |
| Spug 暂存配额 | 全局 1 GiB 每用户 400 MiB |
| 最低保留磁盘空间 | 512 MiB |
| 源内容保留 | 未绑定任务 24 小时 已结束任务 7 天 |

运行、待执行或待核实任务的源内容保留，清理源内容后历史结果仍在。重新上传需要重新选择文件。上述额度是当前默认设置，不适合当作大体积整站备份传输工具。

### 结果状态和异常处理

**已符合**表示目标状态已满足，无需再次变更；**成功**表示已满足该操作实现的核验条件；**失败**要读具体原因；**跳过**要看是否实际处理；**待核实**表示无法确认最终状态。任务“已结束”不代表每个项目都成功。

请求超时可能发生在宝塔已接收命令之后，系统会保留锁，阻止盲目重发。先用“只读核验”查询，再由有管理权限的人员按事实填写结论、原因与依据。取消仅阻止未下发项，已送入宝塔的操作不会因此撤回。需要重试时关联新预检，重新检查并确认。

查看、创建、执行、取消、管理是不同权限。普通用户查看自己的任务，管理权限可查看全部并处理待核实项目，但不单独授予执行权限。官方 API 目录用于搜索参考，收录一个接口不等于已把它接入上述执行流程。

## 09 应用发布

### 发布配置

**用途：**为一个应用定义“从哪里取代码、发到哪台服务器、怎么构建、怎么切换和通知”，减少每次上线重复操作。适合自有项目、Git 管理的网站和有固定部署流程的程序。

**常规发布：**Spug 控制主流程，配置 Git 仓库、环境、目标 SSH 主机、串行或并行、审核、通知、打包过滤规则、部署路径、历史版本存储路径和保留数量。可添加代码检出前后、应用发布前后的钩子。

**自定义发布：**自行排列 Spug 端动作和目标主机动作，按顺序执行命令或传输文件。适合常规流程无法覆盖的构建和部署，脚本作者需要自行负责幂等、错误处理和回退。

**例子：**给官网设置测试和生产两个环境；测试环境发到测试机，生产环境先审核，再按串行方式发布。构建钩子运行在 Spug 服务器或容器，主机钩子运行在目标主机，依赖必须安装在真正执行的那一端。

**路径要求：**常规发布会接管部署路径，首次使用应选尚不存在的专用目录；历史版本存储目录不能放在部署目录内。不要直接把已有客户宝塔网站目录当作可随意接管的目录，先设计站点入口和发布路径关系。

### 构建仓库

**用途：**从 Git 分支、标签或提交生成有名称的构建版本，查看构建日志及该版本关联的发布记录。适合先构建测试，再把同一个构建版本发到多个环境。

**操作：**选应用及环境 → 新建构建 → 选分支、标签或 Commit → 填构建版本 → 运行并看控制台 → 在发布申请中选对应版本。已关联发布申请的构建记录不能随意单独删除。

**例子：**把已测试提交构建为 `web-20261023-01`，生产使用这个版本，不再取可能变化的最新提交。构建成功只说明构建步骤完成，不代表生产已发布成功。

### 发布申请与审核

**用途：**把一次上线变为有版本、目标、申请人和结果的记录。适合团队协作、生产审批及分批上线。

**操作：**新建申请 → 选应用环境、代码版本或构建版本、目标主机 → 写标题和备注 → 配置要求审核时等待有权限者批准 → 执行 → 看逐主机控制台和结果。页面支持的定时发布可指定时间，实际触发可能有最多约 1 分钟延迟。

**例子：**申请“官网修复移动端菜单”，先发测试环境，通过后提交生产申请。审核控制的是原生应用发布申请，不自动成为宝塔面板任务的审批流。

### 灰度与回滚

**用途：**灰度先选部分目标主机发布，确认后再扩展；回滚新建一个回到保留历史版本的申请。适合降低代码上线影响、快速撤回有问题的程序版本。

**例子：**生产有 5 台，先灰度 1 台观察，再发布其余 4 台。异常时选择仍保留的上一版本创建回滚申请，核对目标后执行。

可回滚版本与保留数量有关。程序回滚不等于数据库结构、用户上传文件、外部系统和脚本副作用自动回滚；自定义发布也需要自行设计相应处理。

### 自动触发发布

发布配置提供自动发布 Webhook 等入口，可与代码仓库事件联动。适合测试环境提交后自动部署。按页面提供的触发地址和凭据配置仓库，先验证事件、分支及权限；不要把触发凭据放进公开仓库或公告。自动触发减少手动点击，但仍需设计好目标环境和失败处理。

## 10 流水线

**用途：**把参数输入、构建、远程命令、文件传输及通知连成可重复执行的图形流程。解决“先做甲，再做乙，成功或失败分别通知谁”的多步骤协作问题。

**操作：**新建流水线并设置分组 → 编辑节点和连线 → 为每个节点选模块、目标与执行条件 → 保存 → 运行时填写参数或上传文件 → 在控制台看节点状态和输出，在执行记录追溯。

| 节点模块 | 具体作用 | 使用例子 |
| --- | --- | --- |
| 参数 | 固定参数和运行时输入参数 | 本次发布版本号或环境 |
| 构建 | 在指定构建主机检出 Git 并执行命令 | 构建前端产物 |
| SSH 执行 | 在所选主机运行命令 | 部署后查询服务状态 |
| 数据传输 | 从指定主机路径向目标主机传数据 | 从构建机发送产物 |
| 数据上传 | 运行时从电脑选择文件发给目标主机 | 上传已打包的发布文件 |
| 通知 | 钉钉 飞书 企业微信或推送助手 | 成功通知发布群 失败通知值班人 |

节点可设置上游成功、上游失败或总是执行；起始节点没有上游，条件不作为前置限制。动态参数可用文本、密码框、日期、单选或多选等形式，脚本变量使用界面约定的 `_SPUG_` 前缀。

**例子：**输入版本号 → 在构建机打包 → 传文件到测试主机 → SSH 检查 → 成功通知发布群，失败发另一条通知。数据上传节点会覆盖目标同名文件，不能当作宝塔上传的冻结预检流程。

当前节点列表没有原生宝塔面板任务节点。不要把可视化连线理解为已经具备宝塔批量操作调度。构建和脚本的依赖、目标权限、工作目录仍要按实际执行端准备。

## 11 任务计划

**用途：**按时间或监控告警事件执行 Shell 或 Python，解决每天、每小时重复手动运行的问题。适合定时巡检、固定报表或经过验证的故障处理。

**操作：**创建任务内容 → 设置触发器 → 选择执行对象 → 根据需要配置失败通知 → 保存并启用 → 查看执行记录。触发器包括普通间隔、一次性时间、UNIX Cron，以及监控告警触发；按表单设置生效和结束时间。

**例子一：**每天凌晨 1 点对某个 SSH 主机组做磁盘检查，Cron 填 `0 1 * * *`。实际时刻以任务服务所用时区为准，不能只按浏览器显示推断。生产任务先手动验证脚本和结果判定。

**例子二：**某个进程监控失败后，触发一个只读排查脚本。执行对象可按模式选择 Spug 本机、指定主机或告警关联主机；选“本机”指 Spug 执行环境，不是你的 Windows 电脑。

失败通知可按界面选择钉钉、飞书、企业微信或 Webhook。计划任务输出和失败结果应定期检查；脚本需要用正确的退出码表达异常，不能只打印“警告”却总返回成功。当前不能直接把二开宝塔面板任务作为现成的计划任务类型定时运行。

## 12 配置中心

### 环境管理

**用途：**把开发、测试和生产分开，作为配置和应用发布的共同环境维度。解决同一个参数在不同环境混用的问题。

**操作与例子：**创建“测试环境 test”和“生产环境 prod”，设置唯一标识符和备注；在对应环境中维护不同接口地址。标识符用于 API 和内部引用，建立后按稳定命名维护。

### 服务配置

**用途：**保存多个应用共用的一组参数。适合共享邮件服务、缓存地址、第三方接口地址等公共配置，减少重复维护。

**操作：**新建服务 → 填名称和唯一标识符 → 进入配置 → 选环境 → 增删改键值和备注。生成变量带有 `_SPUG_` 加服务标识符的前缀。

**例子：**“公共缓存”服务为测试和生产分别保存不同 Redis 地址，再让需要它的应用配置依赖此服务。真实密码等仍应限制有权查看配置的人员，配置中心不是对所有成员公开的备忘录。

### 应用配置与依赖

**用途：**保存某个业务应用自己的配置，并声明它依赖哪些其他应用或服务的配置。适合多个程序共享基础参数，又保留各自独立设置。

**操作与例子：**新建“订单服务”应用 → 设置标识符 → 在各环境配置接口地址等 → 配置它对“公共缓存”的依赖。应用接入配置获取后，可取得依赖项，不必在每个应用重复维护同一地址。

### 视图 对比与更改历史

**用途：**用表格、文本或 JSON 查看同一份配置，比较两个环境，追溯谁改了哪个值。

**操作：**进入应用或服务的配置页 → 选环境和视图 → 编辑键值 → 用“对比配置”检查环境差异 → 用“更改历史记录”查看旧值、新值、动作、操作人和时间。

**例子：**生产连接错了测试接口，通过环境对比找到差异，再查更改历史确认原因。配置中心保存数据后，应用仍需通过 API、脚本或既有发布接入读取；不会自动替换所有客户宝塔文件，也不会自动重启程序让它生效。

## 13 监控中心

### 服务器监控

**用途：**集中查看已开启监控的 SSH 主机和宝塔面板资源信息，减少逐台打开宝塔看 CPU 与内存的时间。适合日常值守和发现资源异常后进一步排查。

**开启和查看：**先在主机或宝塔列表打开监控开关，再进“监控中心 → 服务器监控”。可按名称、来源、分组等页面条件查找；从列表的监控图标也可打开同一台详情。

卡片展示 CPU 使用率、内存、负载、多个磁盘挂载点、网络上下行速率和采集时间。无法取得的值显示 `—`，不是零；采集失败会保留旧值并标明过期和原时间，应结合时间阅读。

**自动采集：**默认 60 秒，可选 30、60、300 秒，也可暂停。当前是页面驱动，自动采集当前显示页的卡片；仅开启来源开关不会启动全天后台采集，离开、隐藏或暂停页面后不继续自动采集。共享缓存、目标锁和服务端最多 2 个采集并发用于限制负载，失败时会退避到更长间隔。

**主动采集：**单卡右上“立即采集”针对该台；全局“全部采集”覆盖所有已开启且有权限的来源，包括当前筛选或分页之外的对象，页面串行显示进度。手动操作仍受最短 30 秒间隔、缓存和忙碌退避约束，不保证每点一次都发起新的远端请求。

**合并规则：**同一服务器的 SSH 和宝塔记录需要确认关联后合并。优先 API，只有 SSH 来源也启用且可用时才能后备。共享公网 IP 或 NAT 后的机器不一定相同，不能按 IP 自动硬合并。

**例子：**发现某台内存持续很高，先点“立即采集”确认时间，再运行进程 Top20 模板定位。当前资源卡片没有无人值守 24 小时采集、历史资源曲线或资源阈值自动报警；若要离开页面后仍通知，使用下一节的监控任务。

### 监控任务

**用途：**由后台定期检查目标并报警，适合网站可用性、网络端口、关键进程和脚本检查。它不依赖浏览器一直打开，但需要平台监控和队列等后台服务正常运行。

| 类型 | 检查内容 | 典型场景 |
| --- | --- | --- |
| 站点监控 | HTTP 或 HTTPS 请求状态及可选响应时间阈值 | 官网不可访问或响应变慢 |
| 端口监控 | IP 或域名的指定 TCP 端口能否连接 | 数据库或应用监听端口不可达 |
| Ping 监控 | 目标是否响应 ICMP | 网络连通性观察 |
| 进程监控 | 在 SSH 主机上匹配进程 | PHP-FPM 或业务进程退出 |
| 自定义脚本 | 在 SSH 主机执行脚本 按退出码判断 | 自定义磁盘阈值或业务检查 |

**操作：**新建监控 → 选类型并填目标 → 设置检查间隔、连续失败次数 → 选报警联系组、通知方式和沉默时间 → 测试并启用 → 到报警历史核对通知和恢复。

可选检查间隔为 1、5、15、30、60 分钟，连续失败阈值为 1 至 5 次。站点检查默认请求超时约 30 秒，最终状态码 200 至 399 视为通过；可另设响应时间阈值。端口可连或 Ping 可达不等于业务正确，进程存在也不等于程序能提供服务。

**例子：**每分钟检查官网，连续失败 3 次后通知值班组，沉默 30 分钟避免短时间重复轰炸；故障恢复后有恢复记录和通知。故障发现有检查周期及失败累计延迟，不是故障发生瞬间必定通知。

**脚本规则：**退出码 0 视为通过，非 0 视为失败；如果脚本只打印“磁盘已满”但退出 0，监控不会按这句话报警。通知方式支持当前界面的微信、钉钉、邮件、企业微信、飞书，需配置对应渠道；本页短信选项禁用，不能因为填了手机号就认为可以发短信。

## 14 报警中心

### 报警联系人

**用途：**保存接警人员及其通知地址，解决告警规则里重复填写个人联系方式的问题。

**操作：**新增联系人 → 填姓名及实际使用的邮箱、微信 Token、钉钉、企业微信或飞书机器人等 → 有签名时填对应 Secret → 用页面测试功能验证渠道。手机号字段存在，但是否能发送某种通知仍取决于模块和服务配置。

**例子：**为白班值班员建立联系人，配置邮件与企业微信，再做测试。测试失败先检查平台报警服务、机器人安全设置和网络，不能只确认资料已保存。

### 报警联系组

**用途：**把多人组成接警对象，方便排班或按业务维护，避免每个监控任务都手动选一串人。

**操作与例子：**新建“生产网站值班组” → 选两位联系人 → 在网站监控中引用。轮岗时调整组成员即可；仍应确认各成员有相应渠道，不能假设组里每个人都填了邮件或机器人信息。

### 报警历史

**用途：**追溯监控任务何时故障、何时恢复、持续多久、通过什么方式通知了哪些联系组。适合故障复盘和核对告警链路。

**操作与例子：**按任务或状态查找“官网异常”，对照故障和恢复时间确认持续情况。该页是报警记录查询，不是人工工单闭环。当前页面提示每日清理、保留最近 30 天，长期审计需另行留存。

## 15 系统管理与个人设置

### 登录日志

**用途：**查看账户登录相关记录，辅助识别异常登录与排查登录问题。适合管理员核对某个账户的访问情况。

**操作与例子：**按账户、IP 及成功或失败状态筛选，再对照记录时间，检查某同事报告的登录失败。登录日志不是全部业务动作的统一审计；脚本、发布和面板任务应分别查看各模块执行记录。

### 凭据管理

**用途：**集中保存需要被相应模块引用的账户密码或 SSH 私钥，可选择共享给其他用户。适合 Git 私有仓库访问、云资源接入等对应凭据使用场景。

**操作：**新建凭证 → 选密码或私钥类型 → 填名称、用户和秘密值 → 私钥按需填口令 → 谨慎设置共享。共享后其他用户可以使用该凭据。

**例子：**创建只读 Git 仓库凭据供构建节点引用。这里的凭据、主机独立密钥、系统全局 SSH 密钥、宝塔 API 密钥各有自己的使用位置，不能把同一个输入框当作四者的替代品。

### 账户管理

**用途：**创建人员账户、分配角色及维护账号状态和登录密码，减少多人共用管理员账号。

**操作与例子：**新建“值班运维”账户，填写登录名、姓名、符合规则的密码，分配已建角色；离职或停止使用时按页面入口禁用账户。密码至少 8 位，包含数字、小写和大写字母。已有账户可由有权限者重置密码。

一个账户可拥有多个角色，权限按组合后的较大范围生效。给账户增加一个“限制角色”不会自动收回另一个角色已授予的权限。

### 角色管理

**用途：**控制菜单和按钮功能、授权的主机组及应用发布范围。适合区分管理员、发布人员、巡检人员。

**操作：**新建角色 → 配功能权限 → 配主机组和应用发布权限 → 关联用户 → 用相应账户核对实际可见范围。

**例子：**巡检人员只看被授权主机组并使用巡检模板；发布人员有申请权限，另一个角色有审核权限。执行任务权限本身不等于只能运行某一段只读脚本，角色配置不提供任意脚本的自动安全保证。宝塔任务权限需要分别授予，且宝塔分组当前没有客户级隔离，不应把主机组授权规则直接套到宝塔列表。

### 系统设置

系统设置用于维护平台服务和接入方式，多数需要管理员。以下每项都要按实际使用配置，不是保存一个表单就自动完成外部接入。

**基本设置：**设置调用 Spug 内置服务所需凭据。例：为依赖内置服务的邮件、微信或 MFA 准备授权，不是填写客户宝塔 API 密钥。

**安全设置：**配置访问 IP 校验、登录 IP 绑定及登录 MFA 两步认证。例：限制后台只从固定办公网络访问。启用前核对当前出口和备用登录途径，避免误把自己挡在外面。

**LDAP 设置：**配置目录服务地址、管理员 DN、密码、用户范围、筛选器和字段映射，测试后导入或接入用户。例：让已有企业目录账户登录；未配置 LDAP 的团队继续用本地账户。

**密钥设置：**维护平台全局 SSH 公钥和私钥。例：给新主机部署对应公钥。更换密钥会影响使用该全局密钥的已授权服务器，需要同步安排，不能当作只改后台展示文本。

**报警服务设置：**选择内置邮件服务或配置自定义 SMTP 地址、端口、账号、授权码和发件昵称。例：让监控报警通过企业邮箱发出，保存后测试投递。

**推送服务设置：**绑定推送助手账户并查看对应资源或余额。例：供流水线推送助手节点发送已配置的邮件、公众号、短信或电话通知，部分服务依赖外部账户及费用；它与监控任务里禁用的短信选项不同。

**开放服务设置：**管理访问 Spug 开放接口的凭据。例：让业务程序按接口读取配置中心数据。它授权访问 Spug，不是授权 Spug 访问宝塔。

**关于：**查看平台版本和项目信息，便于报障和确认维护基线。当前二开代码版本还应结合发布记录确认，不能只凭原生版本号识别二开内容。

### 个人中心与通用页面操作

顶栏个人中心用于维护个人基本信息和修改自己的密码；修改密码需要原密码。顶栏提供语言切换和退出登录，语言切换会重新加载页面；重要表单先保存。终端入口及其可见主机受权限约束。

多数已接入公共表格组件的业务表支持拖动表头列分隔线调整宽度，浏览器按页面和表格记忆；双击分隔线恢复该表默认列宽，也支持键盘方向键微调。当前范围为已改造的表格，不包含所有布局分隔线、无表头队列或合并的权限矩阵。

## 16 六个典型工作流程

### 新接入一位客户

**情境：**客户交付两台云服务器和两套宝塔。先建客户分组，登记宝塔入口；需要 API 自动化时补密钥、白名单并测试。获得 SSH 权限的服务器再登记主机。确认同机关系后关联，按需开启监控，再跑只读磁盘与 PHP 检查。

**解决的问题：**入口、授权、分组和监控各自明确，避免只保存宝塔密码就误以为已经具备所有批量能力。交付检查应包含实际连接结果，而不只是“列表中看到了记录”。

### 每日查看多台服务器状态

**情境：**上班后打开服务器监控，先看采集时间与过期提示，必要时“全部采集”；再对关键组运行磁盘和失败服务模板。对异常目标单独进终端排查。

**解决的问题：**减少逐台打开面板，只把时间花在异常主机上。需要无人值守时，在监控任务中配置站点或自定义脚本，不能把打开资源卡片当作已经建立全天告警。

### 批量给网站更新前端文件

**情境：**同一批静态资源要发给多个客户。先备份旧文件，面板任务选上传目录，公共目录填常用站点路径，特殊客户填单独目录。预检重点核对是否多了一层 `dist`、覆盖数是否符合预期。

**解决的问题：**一次发布多个网站，同时处理每台目录不同的情况。执行后逐文件核验，再实际访问关键页面；上传成功不能替代浏览器业务验收。

### 处理即将到期的网站证书

**情境：**先在“网站与证书”筛选 30 天内到期的网站，核对采集时间，必要时主动采集；用 TLS 证书到期模板检查公网域名。点击“填写续签任务”后，在面板任务中读取资源，核对网站、域名、DNS 和 80 端口，再预检并确认申请或续签。

**解决的问题：**把“发现临期”和“执行续签”连起来。前者是检查，后者会变更证书，二者不会自动互相触发；完成后再验证外网真实证书与到期时间。

### 为一组客户维护 PHP 7 4

**情境：**先运行 CLI 版本模板，确认需要维护的主机；再在面板任务中选择“更新 PHP（同分支）”，生成冻结预检，核对受影响网站、预计版本及 CLI 模块基线。先测试机，更新后查看实际版本和模块增减，再检查程序与 FPM，安排生产维护窗口分批处理。模块缺失或无法对照时保留待核实，不因版本号正确就继续整批更新。

**解决的问题：**避免在十几个面板重复找同一个更新入口。不要把同分支更新当作安全支持保证或跨版本迁移；PHP 7.4 的兼容性及维护策略仍需结合程序和官方供应情况判断。

### 发布自有项目并安排值班告警

**情境：**配置测试和生产发布 → 构建一个明确版本 → 测试环境验收 → 提交生产申请 → 审核后灰度一台 → 确认再全量。为生产站点创建监控任务，联系人归到值班组。

**解决的问题：**上线流程、版本记录和故障通知有清晰落点。回滚针对保留版本，数据变更另行处理；资源监控卡片与网站可用性告警配合使用。

## 17 常见问题与排查

### 为什么看不到菜单或按钮是灰色

先确认角色拥有该模块的查看或操作权限；再看是否选了目标、必填项是否完整，以及当前记录是否被任务锁定。查看、创建和执行可能是不同权限，管理员身份之外的账户需分别授权。

运维作业、网站与证书、备份检查台、到期管理和平台健康当前仅超级管理员可用，不能通过给普通角色增加某个按钮权限开放这些入口。

### 巡检结束后在哪里看结果

通过“运维作业”运行的检查，到 **批量执行 → 运维作业 → 执行记录 → 查看结果**，展开逐台检查项，或下载 JSON 报告。只看需处理可集中找出异常、失败、未知和待核实项；查看、刷新或下载不会重跑检查。若使用的是模板加“执行任务”，则去该页面自己的执行记录，两种记录不混在一起。详情见[运维作业指南](operations-center-guide.md)。

### 宝塔网页登录正常 为什么 API 失败

网页登录和 API 是不同授权路径。检查是否开启 API、密钥是否正确、白名单是否为 Spug 实际出口、端口是否可达、API 地址是否错误携带安全入口，以及 HTTPS 信任配置。先在面板列表测试连接，再创建新预检，不要靠重复提交变更来测试连接。

### 为什么没有某个软件 版本或扩展

软件选项来自各台客户宝塔，并受当前适配范围限制。软件商店可见、API 目录可搜索，不代表已开放批量执行；PHP 扩展还要匹配已安装的分支。先读取该台资源并查看阻挡原因。

### 为什么监控没显示 或数值没变

先看来源开关是否开启、当前账户是否有权限、是否需要确认关联；再看采集时间、暂停和页面隐藏状态。立即采集也可能返回缓存或处于最短间隔、忙碌退避，`—` 代表未知，不是零。关闭浏览器后的资源卡片不持续采集。

### 为什么任务显示待核实

可能是请求已到达但应答丢失、队列未完成或接口不能证明最终服务状态。先查只读核验和实际目标，避免同一变更重复执行。管理员人工判定时记录依据，不能只为清掉锁而随意点成功。

### 为什么脚本输出有警告 任务却成功

原生脚本和自定义监控通常根据退出码判断，输出文字不自动决定状态。检查脚本是否在异常时正确返回非零，同时区分“查询执行完成”和“业务健康”。巡检模板也有自己的判定范围，需要读明细。

### 文件上传成功 为什么网站没有变化

先核对最终目录、是否保留了顶层目录、文件名和版本，再看 Web 根目录、浏览器或 CDN 缓存及应用加载方式。上传不自动解压、切换发布版本或重启业务程序，不能只看传输成功就结束验收。

### 是否已经自动备份所有客户数据

没有。历史构建、任务记录和 Spug 暂存都不能替代数据库、站点文件与平台配置备份。客户数据备份、恢复演练以及 Spug 数据库和解密所需配置的保护，需要独立安排。

## 18 能力边界与维护参考

本文覆盖当前导航菜单及关键配套操作。新用户可先阅读第 01 至 05 章；日常网站运维重点使用第 06 至 08、13 至 14 章；负责项目上线和平台管理的人员再阅读发布、流水线、计划、配置与系统管理。

**当前尚未提供的能力：**按客户宝塔分组隔离租户、资源卡片无人值守历史采集与阈值报警、现成宝塔任务计划或流水线节点、所有官方 API 的统一执行、远端文件覆盖自动回滚、DNS 验证和通配符 SSL 申请。需要这些功能时应作为后续开发需求，不能通过现有菜单名称推定已经具备。

**真实执行边界：**上述变更操作具备实现和预检流程，但没有把升级、卸载、真实 CA 签发等全部动作在客户生产环境逐项试跑。每次执行以目标面板实际版本、预检与影响确认为准，首次使用先在受控测试对象验证。

**维护来源：**本手册核对了当前仓库路由、各业务页面、任务执行器、二开用户说明和部署记录。平台后续增加功能或改变行为时，应同时更新本手册和对应模块说明。
