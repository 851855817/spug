# 平台健康使用说明

入口：**系统管理 → 平台健康**，仅超级管理员可见。此页检查 Spug 平台自身，客户服务器继续通过“监控中心 → 服务器监控”查看。

## 日常使用

1. 点击“立即检查”，查看检查时间和各项结果。检查最多缓存 15 秒，不自动轮询。
2. 异常、需关注、待核实都会计入“需要关注”。待核实表示未能完成检查，不能认为正常。
3. 点击“下载报告”保存脱敏 JSON。报告不包含密码、API 密钥、原始日志或客户任务内容。查询失败时，保留的旧快照会明确标记过期。

| 检查项 | 可以判断什么 | 常见处理 |
| --- | --- | --- |
| 数据库 | 简单查询是否成功 | 无法连接时，从宿主机检查数据库容器 |
| Redis 与任务队列 | Redis 可达及执行、计划、监控等待数量 | 大量等待时核查工作进程；等待数不包含正在执行的任务 |
| 八个固定进程 | Supervisor 看到的当前进程状态 | 已停止时查明原因，再选择启动；运行不等于业务成功 |
| 数据盘与 Inode | 持久数据卷空间或文件数量压力 | 排查日志、历史文件和存储容量，不自动删除 |
| 宝塔加密密钥 | 密钥合法且与启动保全指纹一致 | 异常时保留现场，核对持久卷和原始备份，不生成替代密钥 |
| 宿主机诊断 | 容器、HTTP、内存、部署盘及配对备份的独立检查结果 | 报告每 5 分钟采集；超过 10 分钟未更新会提醒 |

## 受控恢复

已停止（STOPPED）、退出（EXITED）、启动失败（FATAL）的指定平台进程才显示“启动服务”。点击并确认后，后端重新读取状态，仅发出一次启动命令并核实结果。Redis、运行中、正在启动或状态未知的进程没有 Web 启动入口。

启动工作进程或调度器可能继续处理已有任务，执行前应核对任务与配置。并发检查或恢复时会拒绝本次操作；重新检查后再处理。超时显示“待核实”，不自动重复启动。启动审计记录在容器持久卷 `/data/spug-health/recovery.jsonl`，仅含时间、操作者 ID、服务名及结果。

后台/API 无法访问时，Web 页面不能完成恢复。通过 SSH 运行宿主机独立工具：

```sh
python3 /opt/spug/platform-health/spug-health.py
```

确实停止且已查明原因时，可手动启动单一固定目标，例如：

```sh
python3 /opt/spug/platform-health/spug-health.py --start spug-db
```

此工具不重启运行中的容器，不删除或重建容器，不自动恢复备份。完整命令及边界见 [宿主机诊断说明](../deploy/platform-health/README.md)。

## 演示地址打不开时

`http://127.0.0.1:18080/` 依赖当前电脑的 SSH 转发。若服务器报告正常、回环 HTTP 可用，但本机 18080 无监听，应检查 Windows 转发任务和连接，不能据此判断服务器宕机。已有自动重连的部署说明见 [Windows 转发](../deploy/windows/README.md)。

## 部署与限制

无需数据库迁移。宿主机独立采集定时器只生成、发布脱敏报告，不执行恢复。安装或移除方式见独立工具说明。停用报告采集后，Web 页面会保留报告并按时间提示过期。

本次交付为运维增强的第一阶段。巡检汇总、失败分类、分批执行和配置差异检查另行实现，当前页面不将这些能力标为已完成。
